## 验收证据与边界

整仓 pnpm typecheck、pnpm test、pnpm build，以及 pnpm check/check:deps/check:singletons、严格 OpenSpec 校验均已通过；最终 PR CI 记录补充在 PR。计费包当前 239 项测试；包含真实隔离 PostgreSQL 的并发/回调乱序/退款响应丢失、重复入账、对账与过期/收回后释放。所有支付请求均为确定性 mock，不使用真实凭据或平台请求。

浏览器覆盖 11 项场景：真实注册/验证赠送/删号、真实客户退款 RPC 与重复申请、普通成员流水隔离、后台动态角色检查和驳回；取消/恢复和部分退款使用真实数据库及领域服务，但在浏览器传输边界注入确定性 PaymentProvider，并只调整展示的 provider readiness。该边界不替代 Stripe/PayPal 或 staging 验收。

回归修复包括：空间中间件保留操作字段至最终输入校验，Webhooks 传递非默认积分宽限，支付诊断脱敏，Cron 全库扫描测试与其他临时数据按依赖顺序隔离。退款审批/API 响应不等于已完成退款，必须等待已验证且金额/ID 相符的回调。队列投递可能重复，资金状态幂等；通知用稳定键去重并在失败后恢复，未承诺邮件传输严格一次。

迁移 0002–0007 只在各 Orca 独立测试数据库验证，没有应用到共享 product_res_dev 或 product_res_staging。只声明了 events/events-staging 队列绑定，没有创建线上资源或部署 P2。无 Stripe/PayPal secret 写入，真实 OAuth/Resend 也未启用。子任务 worktree 与专属数据库在合入后清理，主开发数据库和 staging 不动。

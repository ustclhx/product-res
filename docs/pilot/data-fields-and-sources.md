# 首批字段、口径与数据源选择

更新：2026-09-20。目标：一个合作团队 + 内部自建站团队跑通数据闭环；不预设人工工时门槛。以下是首轮实现口径，具体业务阈值仍由项目负责人确认。

## “字段”和“口径”是什么

字段是系统需要知道的具体信息，例如某个商品卖多少钱、供应商最低订多少件、这次测试花了多少钱。口径是该数值的定义：哪个站点、哪个变体、何时观察、是否含运费/税、哪个币种、统计哪段时间、是事实还是估算。它不特指服务器资源；这里的“来源”是市场数据服务、供应商材料和自己的经营记录。

同样写“价格 20 美元”，可能分别指美国站一件商品的标价、带优惠券的价格、到手价、供应商出厂价。把它们直接相比，会得到错误的成本或利润。写“月销量 500”也可能是页面标签、第三方估算或自营订单统计，三者不能互换。

## 首批最小数据清单

| 用在哪一步 | 字段 | 来源 | 明确口径及缺失处理 |
| --- | --- | --- | --- |
| 纳入候选 | 名称、站点/市场、外部商品 ID 或稳定商品链接、来源、采集时间 | 市场 API 或团队导入 | 这是创建候选的最小身份和追溯集合；不因缺评分或销量估计而禁止纳入 |
| 看市场价格 | 标价、币种、卖家、商品变体/件数；运费/税是否已知 | Amazon/Shopping API | 标价与到手价分开；不把未知运费设为 0；搜索排名只在原查询与地点内有意义 |
| 看竞争/需求线索 | 评分、评论数、搜索位置、赞助标记、页面购买量标签（若返回） | 市场 API | 都是观察到的市场线索；销量标签不是完整订单，缺失标未知，不能单凭此硬排除 |
| 判断供给可行性 | MOQ、采购单价、币种/计价单位、报价有效期、供应商来源 | 报价单/询价/人工录入 | 市场 API 通常不提供你的供应商报价；作为项目确认的必填证据，缺失就分配补证 |
| 做收益假设 | 预计售价、采购/履约/平台/广告费用、退款假设、窗口和数量基数 | 报价、费用表、团队假设 | 假设与事实分开；首轮不要求每项完整才能研究，但缺关键费用不能声称利润可比 |
| 验证任务 | 类型、问题、负责人、期限、条件、实际结果及依据 | 团队询价/样品/小测 | 完成任务不等于商品成功，未达目标也保留实际结果 |
| 结果回流 | SKU/Listing/测试标识与批准轮次映射、统计窗口、币种、销量/收入/退款与费用、来源 | 自营站点/合作团队导出表或人工核验 | 同一 SKU 不同批准轮次需显式选择；测试订单独立标记，不能作为真实经营收益 |

“必须”按业务阶段决定：候选身份与来源必须可定位；硬规则所需材料必须满足该项目质量条件；经营结果可以暂缺费用，但必须明确缺什么。不会要求每个新候选一开始就具备全部字段，也不会靠 AI 把缺值补齐。

## 为什么影响费用和可用性

- 当前商品列表通常一次搜索即可取得；评论正文、卖家报价、历史价格等往往要额外端点或分页。获取 20 条候选列表和逐条拉 20 件商品的所有评论，调用量不是同一量级。
- 单次查询、筛选后查询详情、每日刷新与每小时刷新，成本与配额不同。首轮按需查询，先看前 10 条候选；入选后才考虑补查，不默认全天候采集。
- 90 天历史不是今天抓一次就能得到，需要供应商已有历史服务或从现在开始积累。真实竞品订单通常不是公开数据，付钱也未必获得授权；供应商私有报价则需要团队询价。
- 近似成本可按“搜索次数×页数 + 选中商品数×详情请求数 + 刷新次数×刷新范围”估算，再按各来源计价单位结算。不要把按页计费与按商品计费直接比较。

## 本轮选择

1. **DataForSEO Amazon US**：关键词发现和必要商品信息。官方说明提供 $1 新账号试用额度，无信用卡；充值最低 $50，按用量计费。适合先跑小样本，仍需账号 API 凭据；不是已经实测。[产品与定价](https://dataforseo.com/amazon-product-api)、[接口](https://docs.dataforseo.com/v3/merchant/amazon/products/live/advanced/)
2. **SerpApi Google Shopping US**：自建站方向的商家、价格、评分及供给观察。官方免费计划为每月 250 次搜索，适合少量手动 demo；Google Shopping 覆盖不等于所有独立站，更不等于站点后台销量。[定价](https://serpapi.com/pricing)、[接口](https://serpapi.com/google-shopping-api)

这是基于快速接入门槛的工程选择，不是对数据质量的实测排名。可替代方案是同一 DataForSEO 账号的 Google Shopping 接口；该接口有不同计价单位与异步任务协议，不在本次两适配器实现中暗中替换。[官方说明](https://dataforseo.com/google-shopping-api)

Keepa 留作历史价格/排名补充；Rainforest 留作更深 Amazon 数据备选。eBay Browse 生产准入需申请，不作为首批 live demo 的关键依赖；沙盒不能冒充真实市场。详见两份 research 调研笔记。

经营数据先以真实导出表/人工回填打通，不把尚未选型的 Shopify/WooCommerce 设为前置条件。选定建站系统、有了店铺与授权后，再把同一字段映射替换成自动同步。

## 结果口径

结果记录需要标记 REAL、TEST 或 DEMO。真实数值为 0 可以记录，未知保持空值；测试订单可证明映射链路，不能证明商业成功。不同币种和窗口不自动混算；GROSS 收入在明确退款口径下扣退款，NET 收入不重复扣退款。广告与其他成本缺失时仍允许回填已知项，但贡献利润显示不完整。

闭环验收保留两层证据：技术联调证明真实市场 API、模型和数据回流流程可执行；团队试点证明实际验证/经营记录或真实未上市原因已回流并影响下一轮标准。没有发生销售时不虚构订单，没有完成团队试点时不把技术联调当成真实经营闭环。

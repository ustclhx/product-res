# 合作团队验收指南

范围：研究准备、补证、人工反馈以及后续经营验证。工程发布不等于真实业务验收；缺报价、样品或实际结果时记录缺项，不填零、不代签、不虚构采购批准。

## 进入系统与职责

管理员为每名成员创建独立账号，授予对应工作区：分析负责人负责采集、整理、任务分配和评估；采购协作负责供应商资料、报价和实测录入；决策负责人确认标准、研究结论和反馈。管理员身份不自动赋予项目决策权。项目页先设置真实负责人和期限，再分配内部团队候选的补证任务。

自 2026-09-23 起，团队直接访问 https://product.ezarouter.cc，使用各自业务账号登录，无需 SSH。正式访问域名与服务端 PUBLIC_URL 保持一致；旧 localhost 入口仅保留运维健康检查用途，不再用于业务登录和保存。

管理员通过独立 SSH 身份维护 ECS 和 Cloudflare Tunnel。连接器使用宿主机网络，回源到 127.0.0.1:18081，端口保持仅本机监听。域名切换记录见 [HTTPS 接入回执](public-domain-2026-09-23.json)。

## 新版入口验收

入口调整见 [本轮变更说明](user-journey-2026-09-22.md)。首次登录从“工作台 → 新建项目”进入，两步填写后确认标准并添加候选。已有项目从候选清单继续；补证、评估、验证和结果均从当前事项直接进入。

验收时检查同一事项在工作台、项目事项和全部事项中的负责人、状态和动作一致；切换成员后“需要我处理”随实际责任变化。未分配事项可直接补资料或分配负责人，录入完成后仍需主动确认任务结果。

## 逐项验收

| 场景 | 操作 | 预期 |
| --- | --- | --- |
| 身份隔离 | 两团队分别登录，切换工作区 | 只见本人获授权工作区，候选和原件不串团队 |
| 来源采集 | 查看剩余额度；复用历史批次；显式查询最新 | 复用不发新请求，刷新说明范围/采集时间并消耗限额；失败或结果未知有恢复提示，不自动重发 |
| 来源追溯 | 手工建 OEM，录厂商/原件说明；单独关联市场对标 | 自身来源与对标关系区分；竞品价格不成为 OEM 成本 |
| 采购资料 | 录线下供应商、货号、件/套、阶梯、样品/现货/定制 MOQ、币种、税运费、交期、期限和原件共享链接 | 主口径清楚，参考价不成为核验采购价；另一成员能访问原件 |
| 价格口径 | 核对 Helteko 卖家、变体、两件装、采集时间、税运费；另录 OEM 目标价 | 实際售价和目标估算分别保存，无套装自动拆价 |
| 车型适配 | 先桌面研究，取得样品后按指定 RAV4 配置检查左右前排 | 桌面说明不能替代实测；样品、车型、左右检查不全不能存已核验通过 |
| 研究回流 | 不批准采购，负责人记录真实暂缓/停止理由及启示，提交并确认反馈 | 可无硬规则，可仅变更材料或保留启示；新项目可采用；研究回流独立计数 |
| AI 草稿 | 生成整理草稿，补新证据，再尝试采用旧稿 | 旧稿标过期并阻止直接采用，保留历史与每次已知/未知用量 |
| 批准经营路径 | 材料充分后分析员保存评估，负责人真实决定，执行验证，录真实结果/批准后未上市原因 | 保留批准快照、费用未知不填零，结果来源/时间窗口可追溯 |
| 最终反馈 | 真实复盘、负责人确认、新项目采用 | 不回写旧标准；研究完成不冒充经营效果验证 |

## 每个团队提交的验收记录

记录工作区、操作者与角色、候选/报价/结论/反馈/下一项目标识、执行时间、预期与实际、问题截图、实际工时及返工。不预设工时改善比例。记录保存在团队授权共享位置；仓库只放脱敏汇总。

## 仍需真实材料

- 合作团队：供应商参考/正式报价与原件、样品条件、市场价格核验、目标价依据。
- 后续打样：指定车型配置与实际样品、左右前排实测；缺样品保持待验证。
- 内部团队：明确 Brightroom 候选负责人、任务及期限，由实际成员执行。
- 两团队：各自访问、研究回流或适用经营闭环记录。原 connect-live-selection-pilot 的 9.2 真实结果复盘、9.3 两团队经营路径仍须按原口径验收，研究路径另行记录。

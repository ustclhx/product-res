# 团队试用交付指南

这份指南给合作团队和内部团队使用。它描述一次真实试点从选题到复盘的交接方式。账号、密钥、服务器地址和供应商报价不写在文档里，由试点管理员通过受保护的方式提供。

## 两个职责怎样交接

每个工作区至少安排两个人：

- **分析负责人**：创建项目，拟定研究方向和标准，执行查询或导入候选，补齐材料，保存人工评估，并把候选提交给决策负责人。
- **决策负责人**：确认标准，处理例外，批准验证、退回补证、继续观察或否决；验证和结果复盘后确认下一轮标准建议。

补证成员可以上传报价、询价、样品和测试材料，但不能替分析负责人提交评估，也不能代替决策负责人作决定。每次交接都在候选的历史记录中留下操作者、时间、来源和版本；口头结论要在页面相应的理由或备注中补记。

## 第一次登录

管理员可在“账号管理”中新增成员、设置工作区和角色、启停账号或重置口令，见 [账号管理指南](account-administration.md)。成员使用各自账号；随机初始口令由管理员单独交付。

1. 团队正式入口为 https://product.ezarouter.cc，直接在浏览器打开并使用管理员分配的账号和口令登录，无需建立 SSH 隧道。页面没有公开注册。
2. 一个账号属于多个工作区时，选择本次要进入的团队；登录后只能看到当前工作区的项目、候选和任务。
3. 工作台先展示“需要我处理”，再展示等待他人和进行中的项目。第一次使用可直接点“新建项目”；“全部事项”按项目、负责人、状态和逾期筛选。“试用观察”查看真实材料进度、工时和历史。
4. 先用一条真实候选走通一次；页面上标有“示例数据”的内容只用于演示，不能作为试点材料。

2026-09-23 起采用 Cloudflare Tunnel HTTPS 入口。管理员保留独立 SSH 身份用于运维；团队日常使用只需自己的业务账号。旧的 localhost 入口不再用于登录或保存；域名变更后应在新域名重新登录。

## 当前试点范围

本轮用户明确研究车辆内饰，首个建议切片是车内座椅背收纳（如 `seat back organizer`）。这是建议研究切片，不是已验证商机；详细字段、查询词和证据流程见[车辆内饰收纳试点切片指南](vehicle-interior-pilot.md)。渠道仍为 Amazon US 与 Google Shopping US，查询使用英语和美国口径，每次只观察当前查询返回的前 10 条，不代表市场全量或销量结论。

市场观察与供应商报价必须分开：前者记录来源、q、时间、价格和需求/竞争线索，后者补 MOQ、采购单价、计价单位、报价有效期、供应商来源及履约成本。缺失、冲突和未核验材料进入补证任务；不填零、不把市场标价当采购成本，不把 AI 文字当事实。

当前 DataForSEO、SerpApi 与 DeepSeek 已取得真实调用回执；来源状态仍以登录后的页面为准。市场来源累计请求上限以页面为准，当前配置每团队每来源 10 次；额度用完时可打开已有批次继续研究，也可用手工添加或 CSV 补充材料。

## 一次试点的操作顺序

### 1. 选题与项目标准

在工作台或“选品项目”点“新建项目”：第一步填写方向、渠道、市场、目标与限制；第二步安排分析和决策负责人。可先保存草稿，随后会直接进入项目的标准页面。决策负责人选择必需材料并确认标准后，页面进入添加候选。默认先核验材料，不预设硬性淘汰门槛；如需门槛，由团队明确填写确认。标准、负责人设置及历史可从项目次级导航查看。

### 2. 查询、纳入候选

在项目候选清单右上点击“添加候选”，再在“把机会纳入候选池”中选择“按方向发现”，选可用来源，输入方向并查询。查询结果是该来源在当前时间返回的有限线索，不代表市场全量或真实销量。逐条勾选要研究的商品，再点击“纳入已选择候选”。

来源不可用时，可使用“手工添加”或“CSV 导入”。手工至少填写商品名称；有的话补外部商品标识、SKU 和来源链接。CSV 先生成预览，确认有效行、重复行和无效行后再写入。保留来源链接、文件名或记录编号，方便回看。

查询结果进入候选池只是**显式纳入**，不是通过初筛，也不是批准验证。候选页的“候选来源与进入记录”应能说明它来自方向发现、手工录入或 CSV 导入。

### 3. 未核验观测与供应商补证

打开候选的“1. 收集资料”。市场返回的价格、评分、评论数、排名或页面标签先作为观测保存；不能把第三方估计写成团队订单，也不能把缺失写成 0。来源定位、观察时间、币种、变体和核验状态要尽量填全。

工作台的事项主按钮会打开对应的报价、适配或核验表单；“待分配”的事项可先直接补充，或由分析负责人点击“分配负责人”指定执行人和期限。同一事项在工作台、项目事项和全部事项中使用相同状态，逾期不会重复列出。

供应商补证由补证成员或分析负责人负责。常见材料包括 MOQ、采购单价、计价单位、币种、报价有效期、供应商来源、运费/履约费和询价原件。页面中标为“未核验”或“有冲突”的证据不能满足硬规则；建立补证任务，拿到材料后新增一条当前、已核验的证据，再重新执行初筛。不要覆盖旧证据。录入不等于核验，核验也不自动结束任务：任务负责人仍需点“更新事项进度”，选择完成依据并保存。OEM 研究参考值只满足该阶段的材料准备，不能替代正式采购或实车核验。

等待真实报价、销量、费用或结果时，保持空值并写明“待供应商补证”或“待团队提供”。不填零、不粘贴猜测值，也不把 AI 生成的文字当事实。

### 4. AI 草稿与人工修订

初筛材料齐备后进入“2. 评估与决策”中的“评估整理”。分析负责人可以点击“整理评估草稿”。草稿按需求、竞争、差异化、供给成本、风险五个维度组织，只能引用当前候选证据。

草稿必须逐项人工核对：修正错误引用和判断，补充未知项、反证和假设，说明预测的币种、时间窗口和收入口径。点击“复制到人工修订草稿”只会填入可编辑内容；保存“人工评估版本”才形成业务快照。模型来源、版本和采用记录会随保存结果保留。

### 5. 人审与验证

分析负责人在“评估与决策”中的“提交与决策”提交当前评估。决策负责人根据当前标准、已核验证据、未知项和反证选择：批准验证、退回补证、继续观察或否决，并填写理由；退回必须留下具体问题。

批准后到“3. 获批验证”或“全部事项”建立询价、样品或小测任务，填写负责人、期限、完成条件和目标。完成任务要写实际结果并勾选候选证据；“完成任务”本身不等于商品成功。决策负责人再记录“继续验证”“进入结果跟进”或“停止验证”。

### 6. 真实/测试回填与复盘

在候选“4. 结果复盘”中手工录入或预览 CSV 后确认导入。每条结果选择 **真实经营结果（REAL）** 或 **联调测试数据（TEST）**，并填写批准轮次、SKU/Listing/测试标识、来源定位、来源修订、统计窗口、币种、销量和收入口径。

没有上市时选择“该商品未上市”，写清原因，不填写虚构销量或金额。经营指标没有取得就留空；系统会标为缺失，不按零计算。GROSS 与 NET 只能按实际口径填写，退款不能重复扣除。

结果窗口结束且复盘完成后，分析负责人记录偏差原因；决策负责人确认或拒绝“下一轮标准”建议。确认建议会建立新的标准版本，历史评估和批准记录保持原样。

## 可直接照抄的试点检查表

### 开始前

- [ ] 团队入口、账号、口令已由管理员分别交付；未把密钥写入表格或聊天。
- [ ] 两个工作区名称和成员已确认；分析负责人、决策负责人、补证成员职责已分清。
- [ ] 目标渠道、市场、研究方向、轮次、截止时间和人工记录方式已确认。
- [ ] 本轮标准、必填证据、费用口径和验证条件已由决策负责人确认。
- [ ] “来源状态”以现场页面为准；未显示可查询时改用手工或 CSV，并记录原因。

### 每个候选

- [ ] 商品名称、市场、外部标识或稳定链接、进入来源和采集时间可追溯。
- [ ] 查询线索已明确纳入；未把查询结果直接当作通过或批准。
- [ ] 价格、币种、变体、运费/税是否已知分别记录。
- [ ] 需求/竞争线索标出观察时间和来源；第三方估计没有写成订单事实。
- [ ] MOQ、采购单价、计价单位、币种、报价有效期、供应商来源齐全，或已建补证任务。
- [ ] 未核验、过期、冲突和缺失材料仍保持原状态；没有填零或假核验。
- [ ] AI 草稿已逐项核对，人工判断、未知项、反证、假设和引用已保存。
- [ ] 决策负责人已留下批准、退回、观察或否决及理由。
- [ ] 验证任务有负责人、期限、完成条件和实际结果；结论已由决策负责人记录。
- [ ] 结果明确标 REAL/TEST；未上市写原因，未知经营字段留空。
- [ ] 复盘和下一轮标准建议已由相应负责人处理。

### 交付前

- [ ] “试用观察”的真实闭环进度只由真实材料组成；工程测试、TEST 和示例不计为完成。
- [ ] 每个结果都能回到候选、批准轮次、来源定位和统计窗口。
- [ ] 对“未发生”“未提供”“无法核验”分别写清原因；没有用 0 代替未知。
- [ ] 现场记录已注明 DataForSEO、SerpApi、NewAPI 当前状态；没有把代码可用写成账号已打通。

## 材料字段小抄

| 材料 | 至少记录 | 不能替代的内容 |
| --- | --- | --- |
| 市场线索 | 商品名、渠道/市场、外部 ID 或链接、来源、采集时间 | 不等于订单、销量或批准 |
| 价格观察 | 标价、币种、卖家、变体/件数、运费/税是否已知 | 不把未知费用写成 0 |
| 供应商报价 | MOQ、采购单价、币种、计价单位、有效期、供应商、文件/行号 | 市场 API 线索不能代替报价 |
| 验证材料 | 任务类型、问题、负责人、期限、条件、实际结果、证据 | 完成任务不能代替业务成功 |
| 经营结果 | REAL/TEST、批准轮次、SKU/Listing/测试标识、窗口、币种、销量、GROSS/NET、收入与费用来源 | TEST 不能计入真实经营效果 |
| 未上市记录 | 未上市状态、原因、来源定位 | 不填虚构销量或金额 |

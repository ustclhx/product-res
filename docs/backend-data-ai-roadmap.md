## 建议的端到端链路

```text
授权的数据源 / 团队文件 / 店铺经营数据
  → 采集任务与原始响应记录
  → 字段归一、商品身份映射、口径和质量检查
  → 候选来源 / 证据版本 / 经营结果版本
  → 确定性初筛 + 节点 AI 整理
  → 人工评估、批准与验证
  → 结果对账和偏差复盘
  → 人工确认的下一轮标准 + 脱敏评测样本
```

外部观测、供应商估算、模型推断分别标注。接口成功不等于证据已核验；市场估计也不能当作本店成交事实。pilot 请求限额按工作区累计任务预留，不按月自动 reset；结果未知不自动重试。

## 分阶段交付

### 已完成代码：可控的真实试点后端

已实现 `demo`/`pilot` 分离、控制库和独立工作区、服务端认证、持久任务 worker，以及外部调用边界。可执行初始化和配置步骤见 [pilot runtime 指南](pilot/runtime.md)。

- 保持模块化单体和现有业务对象。把 provider、时钟、工作区模式及密钥配置集中注入；演示与真实试点使用独立数据空间，真实界面不能调用示例重置。
- 从服务端会话确认操作者与项目权限，不接受浏览器任意声明 actor。若共享部署，所有查询、命令、任务及附件均校验工作区归属。
- 增加持久任务与 worker，支持取消、超时、有限重试和失败恢复。提交任务的短事务保存输入快照与执行记录；外部网络调用在事务外执行；落库时重检版本。
- 重试采用稳定任务键；worker 重复交付不能创建重复证据或结果。外部调用超时可能已产生费用，因此调用费用不能宣称严格只发生一次。
- 真实数据使用实际 UTC 时钟；固定时钟仅用于演示和测试。建立备份/恢复及脱敏日志；需要共享并发写入时再确定 PostgreSQL 迁移方案和回滚步骤。

验收：越权与跨工作区读取/写入被拒绝；重启后任务可恢复；模拟超时/重复交付无重复业务写入；外部慢请求不长期占用写事务；备份可恢复；真实工作区不被示例重置触及。

### 已完成代码：首批真实市场数据纵向打通

原建议变更名：`connect-first-market-data-source`，现纳入统一提案。首批采用 DataForSEO Amazon US 与 SerpApi Google Shopping US 小范围手动查询，服务 Amazon 精品团队及自建站团队的市场观察；后者不代表自建站真实订单。eBay 保留业务骨架，本轮不承诺生产数据接通。

| 数据类别 | 候选接入方式 | 在工作流中的用途 |
| --- | --- | --- |
| 市场/竞品 | 授权数据服务或可用的平台接口；采购前核验字段、地域、时效、留存与展示范围 | 发现候选、价格/竞争/需求信号；估算保持估算属性 |
| 团队业务材料 | 已有选品表、供应商报价、样品与履约记录 | MOQ、成本、交期及验证证据；文件与行号可追溯 |
| 自营经营结果 | 授权的店铺、ERP、广告与支付数据；先用团队导出表校验口径 | 实际销量、退款、广告及履约成本；用于结果回流 |

第一条连接器先覆盖“查询 → 查看候选 → 明确纳入 → 补齐关键证据”。将 discovery batch、查询参数、覆盖范围、条目快照与 source_ref 持久化，纳入时校验条目确实属于该批次，不能按浏览器传入内容直接信任。

每条外部观测保存 provider/version、源商品标识、站点、观测与采集时间、原始记录引用、映射版本、单位/币种/窗口、过期策略、事实或估算分类。原始正文的保存方式和期限服从来源授权，不能默认永久保存。数据更新追加证据版本；相同内容重复同步不增加证据权重。跨平台同款关系需要明确匹配依据或人工确认。

验收：选定试点样本能端到端追溯；无覆盖不伪造结果；缺字段进入补证；过期/冲突显式提示；限流与失败可恢复；重复刷新不重复建候选；记录每次同步成本与有效证据覆盖率。

### 已完成代码：接入一个真实模型，先上线评估整理

建议变更名：`connect-grounded-node-assistant`。阶段 1 完成后可与阶段 2 的适配工作并行，但正式试用验收依赖真实、可追溯证据。

- 首先实现“已有证据 → 五维评估草稿”，然后接补证清单与偏差复盘。用户仍点击业务动作，无需写提示词。
- 输入是不可变的证据、标准、历史人审问题及输入摘要；输出是符合 schema 的草稿、引用、未知项与建议。禁止把外部文本内的指令当作系统指令；不提供批准、采购、刊登或投放工具。
- 后端验证引用属于当前候选与输入版本、事实性陈述有依据、字段结构合法。引用存在只证明可追溯，是否支持结论还需评测与人工复核；金额及硬规则继续由确定性服务计算。
- 提示词、模型、schema、输入、输出、耗时、用量和错误分别留版本。旧任务完成时如输入已变化，只保留为旧版本结果，不能覆盖当前草稿或推进状态。
- 单任务和工作区预算、超时与重试有上限；失败保留人工整理入口。初期一个模型适配器即可，不提前建设多 Agent 自主编排。
- 建立脱敏黄金样本，覆盖缺失、过期、冲突、跨候选引用、恶意来源文本、不同渠道、退款口径及退回重评。模型或提示词变更需回归，关注有依据的判断、人工纠错工时、延迟和成本；质量阈值在试点前约定。

验收：合法引用与结构检查通过；不可用或不合格输出不能成为正式评估；不会自动批准；输入变化不会使旧输出被当作当前输出；与人工流程比较时计入核验和纠错工时。

### 4. 用真实经营结果验证闭环

建议变更名：`connect-outcome-feedback-pilot`。

- 建立候选—批准轮次—Listing/SKU/测试标识映射。先用一个团队的真实导出表完成对账，再自动同步相同口径，避免连接器已通但结果无法归属。
- 订单、退款、广告、采购与履约成本分别保留来源和窗口；明确收入净额/总额、时区及币种。缺费用时不补零；退款或账单迟到时追加修订并保留原对照。
- 把“规则建议”“人工确认/拒绝理由”“实际结果”“AI 草稿被如何修改”形成结构化反馈记录。先支持规则迭代与模型离线评测，不默认用客户数据训练或跨团队复用。
- 统计获批结果覆盖率、补证次数、退回率、人工总工时、AI 修订工时和每次评估成本；经营效果需等观察窗口结束并说明样本选择偏差，不能只看成功或已回填候选。

验收：获批候选可对到结果或明确未上市；费用与店铺/团队账单可核对；新标准用于下一轮且不改历史；能够报告真实投入与缺失覆盖，不预先承诺效率或选品成功率提升。

## 已确认的试点选择与后续配置

1. 试点是一个合作团队和内部自建站团队，分别使用隔离工作区；来源选择及逐阶段字段解释见 [字段与数据源说明](pilot/data-fields-and-sources.md)。账号凭据与真实样本可在接入阶段提供。
2. 必需字段按“纳入、初筛、评估、结果”逐步补齐，不要求首次发现就拥有全部数据。商品标价来自市场 API；MOQ/采购报价来自团队供应资料；真实订单与费用来自自己的经营记录。历史深度、详情分页和刷新频率影响采购与请求成本。
3. 部署采用同机 ECS `43.106.17.72` 和 NewAPI，独立服务、凭据、数据卷与入口。初期保留 SQLite 和单 worker 并发，暂不新增常驻 PostgreSQL/Redis；只读检查结果见 [ECS 核查记录](pilot/ecs-readiness-2026-09-20.md)。密钥、预算及团队 HTTPS 入口仍是上线配置项。
4. 验收以两个团队各自跑通真实数据闭环为准，工程联调与团队真实结果分开记录。人工工时按试点实际观察，不将预先建立工时基线或改善比例作为准入门槛。

第一轮建设目标是让真实候选完成“市场来源 → 证据 → AI 草稿 → 人审 → 验证 → 结果/未上市原因 → 反馈 → 下一轮标准”。结果先以真实人工/CSV 回填，自动店铺同步等后续平台确定再接。完整开发拆分见 [实施任务](../openspec/changes/connect-live-selection-pilot/tasks.md)。

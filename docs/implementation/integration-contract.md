# Implementation seam (2026-09-20)

Supervisor owns app/main.py, app/core.py, app/selection/contracts.py, app/persistence/**, app/api/routes/__init__.py, shared frontend API/shell, global tests/checks/OpenSpec tasks. Workers own only delegated modules. No recursive delegation. Preserve everyone else's changes.

## Backend seam
- `from app.core import Command, DomainError, execute, require_role`.
- Command is Pydantic BaseModel with extra forbid: actor_id:str, expected_version:int|None=None. Workers derive typed command schemas; use Literal enums for JSON, UTCModel aware timestamps if needed. All writes require Idempotency-Key header; execute checks it.
- `execute(request: Request, command: Command, target_id: str|None, action: str, operation: Callable[[Tx,str],dict[str,Any]]) -> dict[str,Any]`. It gets store from request.app.state.store; begins immediate SQLite transaction; validates actor, target expected_version; checks command receipt scoped actor+action+target+key, validates same payload hash, writes atomic audit+response receipt. fn gets tx and actor_id. Return domain result or `{'item': entity}` if convenient but keep consistent endpoint by endpoint. Existing responses JSON fields snake_case.
- `DomainError(code: str, message: str, status: int=422, details:dict|None=None, commit:bool=False)`. commit=True only for recording submission invalidation / failed node attempts before returning domain error. Other failures roll back.
- `require_role(tx, project:dict, actor:str, role:str)` role analyst/decision/contributor; project analyst_id/decision_owner_id; contributor allows known actors to supply evidence/tasks, action-specific stricter check as needed.
- `from app.persistence.store import Tx, Store`.
- Tx `get(id:str, kind:str|None=None)->dict` raises NOT_FOUND; `list(kind:str, *, project_id:str|None=None,candidate_id:str|None=None)->list[dict]`; `add(kind:str,data:dict,*,entity_id:str|None=None,project_id:str|None=None,candidate_id:str|None=None)->dict`; `update(id:str,changes:dict)->dict` increments version; `audit(actor,action,entity_id,details=None)->None`; `now: datetime` aware fixed demo clock. Entity includes id,kind,version,created_at,project_id,candidate_id plus supplied data. Do not shadow reserved keys. New IDs uuid4. immutable kinds criteria/evidence/evaluation/decision/submission/outcome/override/validation_conclusion/node_run: update forbidden. Store `transaction(now:datetime|None=None)` context manager; Store(path) initializes schema; reads use transaction as well. Foreign key project/candidate references entities.
- app.state.clock callable -> datetime, default fixed 2026-09-20T08:00:00Z. tx.now provided by execute. Query routes `with request.app.state.store.transaction(request.app.state.clock()) as tx:`.
- Actor IDs analyst, owner, contributor; GET /demo returns actors, sample version, clock, initialized. demo mode only, no real auth.
- APIRouter modules expose `router` WITHOUT /api/v1 prefix; supervisor includes prefix. No edits to main by workers.

## Canonical entity fields / kinds
project: name,channel AMAZON|EBAY|DTC,market,direction,goal,constraints,analyst_id,decision_owner_id,current_criteria_id.
criteria: rules=[{field,operator:'lte'|'gte'|'eq',threshold:str,unit,currency:str|None}],required_evidence:list[str],template_id,template_version,confirmed_by,confirmed_at,parent_revision_id; project_id linked. Template default required evidence moq, procurement_cost; actual forecast estimates never hard inputs.
candidate: title,external_id,source_url,business_status PREPARING|IN_REVIEW|RETURNED|VALIDATING|WATCHING|REJECTED|OUTCOME_PENDING|REVIEWED,screening_status UNCHECKED|PASS|NEEDS_EVIDENCE|EXCLUDED|OVERRIDDEN,current_evaluation_id,current_submission_id,approval_id,sku,market,is_demo. source records kind source with candidate_id/project_id.
evidence: field,value(str|None),unit,currency,window,source_locator,observed_at,valid_until,epistemic_kind FACT|ESTIMATE|ASSUMPTION,verification VERIFIED|UNVERIFIED|CONFLICT,supersedes_id,is_demo. New independent conflicting observations do not implicitly overwrite; explicit supersedes_id for updates.
evaluation: criteria_id,evidence_ids,input_hash,dimensions,unknowns,counterevidence,assumptions,forecast (basis fields + numeric metrics),assistant_versions; snapshot immutable.
decision: action APPROVE|RETURN|WATCH|REJECT,reason,questions,actor_id,evaluation_id,criteria_id. APPROVE sets candidate.approval_id=decision.id, business_status VALIDATING; also adds kind obligation with candidate_id,project_id,approval_id,status PENDING. Authoritative immutable evaluation found via approval decision.evaluation_id.
task: type EVIDENCE|QUOTE|SAMPLE|TEST,question,owner_id,due_at,completion_criteria,expected_metrics,approval_id,state TODO|IN_PROGRESS|BLOCKED|DONE|CANCELLED,result,evidence_ids,target_met,reason,field (for EVIDENCE).
outcome: approval_id,status RECORDED|NOT_LAUNCHED,window_start,window_end,currency,units(str|None),revenue_basis GROSS|NET,metrics dict[str,str|None] keys revenue,refunds,procurement,platform,fulfillment,advertising,other; source_locator,is_demo,reason,sku.
feedback: outcome_id,before_rules,after_rules,reason,status PROPOSED|CONFIRMED|REJECTED,new_criteria_id (mutable via update). Confirmation creates criteria for future new-project use, does not update original project current_criteria_id.

GET /projects => {items:[]}; GET /projects/{id} => {project,criteria_versions,candidates}; GET /candidates/{id} supervisor supplies {candidate,project,criteria,evidence,screenings,overrides,evaluations,submissions,decisions,tasks,outcomes,obligations,feedback,activity,node_runs,validation_conclusions}. GET /tasks => {items:[]}. Other service endpoints document actual payloads in own API notes under docs/implementation/ (no shared doc edits).

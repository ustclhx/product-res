# 数据源接入设计（讨论稿）

更新：2026-10-20。状态：**已定稿**（第 7 节决定记录）。实施见 OpenSpec change `add-accuracy-store-tracking`。本期不做：Keepa（跑通后再评估）、自有店铺（等合作方提供数据）、Semrush。

本文在已实现的数据层框架上展开，不重复框架本身：
- 框架：连接器契约、额度账本、原始存档、观测长表、文件导入、数据质量，见 `openspec/changes/add-data-source-hub/design.md`。
- 原数据源清单见 `docs/plan/selection-workbench.md` §3。

三类数据源：

1. **付费数据，经 AIsa 一站式接入。**
2. **自建数据。** 追踪跟卖店铺和热门店铺，记录它们的新品和出单。
3. **自有店铺数据。** 用真实销售回验，做漏斗分析，给出建议。

---

## 0. 目标：精确性第一

本系统里"精确"指三件事：

1. **说得清。** 每个数都标明它是什么性质：真值、官方值、页面展示值、第三方估算，还是推算。
2. **算得出误差。** 估算类数据有可量化的误差，并持续用真值校准。
3. **不装懂。** 缺失就是缺失，区间就是区间，单一来源就标"未交叉验证"。

所以，数据源设计的核心是**分级 + 校准 + 抽检**，而不是"接的越多越好"。第三类（自有店铺）除了做漏斗分析，更重要的作用是**提供真值，校准前两类**。

### 0.1 数据可信度分级

每条观测在现有的"获取方式"字段之外，再记录一个层级：

| 层级 | 含义 | 例子 | 默认用法 |
|---|---|---|---|
| T0 真值 | 自有店铺的实际数据 | 自有订单、Sales & Traffic 报表、eBay 流量报表 | 校准基准、回测标签 |
| T1 平台官方接口 | 平台 API 直接给出的值 | eBay Browse 的价格、可售量、`estimatedSoldQuantity`；SP-API 费用预估 | 主值优先 |
| T2 平台页面展示值 | 平台对外展示、经第三方接口抓取的值 | Amazon 的 "bought in past month" 徽标、BSR、评论数、价格（经 DataForSEO） | 主值候选；存为区间 |
| T3 第三方估算 | 工具商用自有模型给出的值 | Jungle Scout、卖家精灵的销量估算 | 并列展示，按校准误差排序 |
| T4 系统推算 | 本系统由其他数据推出的值 | 快照差分销量、BSR 换算销量、评论增速换算销量 | 必须附推算方法和误差 |

**主值规则调整：**
- 现有规则是按来源优先级取第一个有值的来源。
- 改为：先比层级；同层级内，按**校准误差**从小到大排序。
- 还没有校准数据时，回退到人工配置的优先级。

### 0.2 区间值

很多高价值信号本身是区间。例如 Amazon 的 "1K+ bought in past month" 只表示 `[1000, 2000)`，并不是 1000。

- **约定：** 观测表增加 `value_low` / `value_high`，点值时两者相等。
- **展示：** 页面显示区间。
- **算法：** 取区间中点或对数中点参与计算，置信度的"数据覆盖"维度按区间宽度降权。
- **禁止：** 不把下界当点值使用，否则会系统性低估。

### 0.3 校准闭环

```
自有店铺真值（T0）
   │ 同一 ASIN / listing、同一天
   ▼
对照各来源对它的估算值（T2/T3/T4）
   │
   ▼
每个来源 × 平台 × 类目的误差统计
   │  中位绝对百分比误差、偏差方向、区间命中率
   ├──→ 主值排序（0.1）
   ├──→ 置信度维度 ④ 来源一致性 / ⑩ 历史命中率
   └──→ 推算模型参数（BSR→销量、评论增速→销量）按类目拟合
```

- **自有样本少时：** 误差统计显示样本量，样本不足（默认 < 10 个 ASIN·月）时不参与排序。
- **补充校准样本：** 在追踪的店铺里，有些商品能拿到 T1 已售量（eBay `estimatedSoldQuantity`），也作为次级校准样本。

### 0.4 人工抽检（金样本）

- **抽样：** 每周从被追踪的商品里随机抽 20 个，在工作台给出"打开原页面核对"清单。
- **核对：** 人工填写页面上实际看到的价格、徽标、评论数、可售状态。
- **统计：** 系统计算各字段与采集值的一致率，作为数据中心的**准确率 KPI**。
- **告警：** 一致率低于 95% 时，数据中心标红，并暂停该来源的主值资格。
- **时间成本：** 每周约 10 分钟。这是发现上游接口悄悄变更字段含义的唯一可靠手段。

### 0.5 其他保留规则（已在框架中）

缺失不补零；原始响应存档 90 天，可回放；同步后做质量检查（缺失、突变、来源差异、新鲜度）。

## 1. 付费数据源：经 AIsa 一站式接入

### 1.1 核验结论（2026-10-20，依据 AIsa 公开 OpenAPI，未使用 key）

AIsa 是一个 API 网关：

- **认证：** 一个 `Authorization: Bearer <key>` 访问所有上游。
- **地址：** 数据接口统一为 `https://api.aisa.one/apis/v1/<provider>/...`。
- **计费：** 按调用计费。DataForSEO 接口的计费方式是"按上游响应中的费用 × 1.0"，即与 DataForSEO 原价一致；精确报价用免费的 `batch_quote` 获得。
- **限额：** key 本身可以设置消费硬上限。

与本项目相关的接口：

| 上游 | 接口（AIsa 路径前缀 `/apis/v1/dataforseo/`） | 提供什么 | 用途 |
|---|---|---|---|
| DataForSEO Merchant Amazon | `merchant/amazon/products`（task_post / tasks_ready / task_get，也有 live） | 关键词搜索结果页：ASIN、价格、评分、评论数、**`bought_past_month`**、Best Seller / Amazon's Choice 标识、配送 | 方向内的新品发现；热门商品发现 |
| DataForSEO Merchant Amazon | `merchant/amazon/asin` | 单个 ASIN 详情，含上述字段 | **被追踪商品的每日快照**（主力） |
| DataForSEO Merchant Amazon | `merchant/amazon/sellers` | 某 ASIN 的在售卖家及报价 | 跟卖竞争：卖家数、最低价、Buy Box |
| DataForSEO Labs Amazon | `dataforseo_labs/amazon/bulk_search_volume`、`related_keywords`、`ranked_keywords`、`product_rank_overview`、`product_competitors` | Amazon 站内关键词搜索量；某 ASIN 排名的关键词；竞品 ASIN | 品类洞察、需求维度 |
| DataForSEO Keywords Data | `keywords_data/google_trends/explore`、`dataforseo_trends/*`、`google_ads/search_volume`、`dataforseo_labs/google/historical_search_volume` | Google 趋势、搜索量历史 | 季节维度（现有连接器已实现） |
| eBay（AIsa 自有） | `/apis/v1/ebay/search` | eBay 搜索结果页抓取（标注为 test） | 仅作 eBay 官方接口不可用时的兜底 |
| TikHub TikTok Shop | `/apis/v1/tikhub/tiktok/shop/web/*` | TikTok Shop 热卖榜、商品详情、店铺商品、评论 | P2，做趋势前哨，本期不做 |
| Semrush | `/apis/v1/semrush/*`（20 个） | Google 网页 SEO：域名、关键词、外链 | 与 Amazon/eBay 选品关系弱，**本期不接** |

**AIsa 没有的（需要另行订阅或另找来源）：**

- **Keepa：** Amazon 的 BSR 历史、价格历史、**卖家店铺商品列表**。这是 Amazon 店铺追踪的最大缺口，见 §2.3。
- **Jungle Scout / 卖家精灵 / Helium 10：** 销量估算（T3）。
- **Amazon 评论正文：** 目录里 DataForSEO 没有 Amazon 评论接口，品类洞察的"差评痛点"缺少来源。
- **官方接口：** Amazon SP-API 与 eBay 官方 API 都不经过 AIsa，需各自的开发者凭据（免费）。

### 1.2 接入方式

- **连接器复用。** 现有 `packages/connectors/src/dataforseo.ts` 增加"传输方式"配置：
  - `direct`：原 Basic 认证；
  - `aisa`：Base URL 为 `https://api.aisa.one/apis/v1/dataforseo`，使用 Bearer。

  请求体、响应体和归一化完全复用。观测的来源仍记为 `dataforseo`，另记渠道 `aisa`。这样以后换回直连，历史数据也连续。
- **凭据。** 放服务器 `secrets/optional/AISA_API_KEY`，0600。数据库和日志里都不出现。
- **新增的 Amazon 能力**写在同一个连接器里：`amazon-products`（搜索）、`amazon-asin`（快照）、`amazon-sellers`（报价）、`amazon-keywords`（Labs）。
- **计费方式。** 日常批量任务用 standard 队列（`task_post` → `tasks_ready` → `task_get`）。人工"立即刷新"用 live 接口，更贵但即时。
- **两层预算：**
  1. AIsa key 本身设置月度硬上限，即使系统出错也不会超额；
  2. 本系统账本按微美元预扣，并按响应 `cost` 结算，这部分已实现。

  对账时，以 AIsa 控制台的消费记录核对账本，差异超过 5% 告警。
- **探测（probe）：** 用免费的 `batch_quote` 和 models 列表验证 key 是否有效，不产生费用。

### 1.3 成本估算（量级，须用 batch_quote 实测）

AIsa 目录的参考估算：Amazon Merchant 任务约 $0.012/次，Labs Amazon 批量搜索量约 $0.136/次（一次最多 1000 个词），Google Trends 约 $0.0012/次。standard 队列通常更便宜，实际以报价为准。

| 任务 | 规模假设 | 频率 | 月成本量级 |
|---|---|---|---|
| 被追踪 ASIN 快照 | 热点 300 个每日 + 普通 1500 个每 5 天 | 每日约 600 次 | 约 $216 / 月（按 $0.012） |
| 方向关键词搜索发现新品 | 10 个方向 × 20 个词 × 1 页 | 每 3 天 | 约 $24 / 月 |
| 跟卖报价（sellers） | 仅线索商品约 100 个 | 每日 | 约 $36 / 月 |
| Amazon 关键词搜索量 | 2000 个词 | 每周 | 约 $1 / 月 |
| Google Trends | 200 个词 | 每周 | < $1 / 月 |

ASIN 快照是成本主体，所以：
- **分档追踪**（热点每日、普通 3–7 天、冷门停追）是必要设计。
- **档位自动调整：** 7 天内 `bought_past_month` 上升或进入线索，升为热点；30 天无变化，降一档。

## 2. 自建数据：店铺追踪

目标：盯住跟卖对标店铺和热门店铺，回答三个问题：
1. 它们**最近上了什么新品**？
2. **哪些新品开始出单**？
3. 店铺整体在**往什么方向迁移**？

### 2.1 店铺池

| 字段 | 说明 |
|---|---|
| 平台 / 站点 | eBay US、Amazon US 等 |
| 店铺链接 | 粘贴即可，系统解析出平台卖家 ID：eBay 店铺名或用户名；Amazon 的 `seller=` / `me=` 参数 |
| 类型 | 跟卖对标 / 热门店铺 / 观察 |
| 关联方向 | 可多个；与现有选品方向的对标店铺合并 |
| 加入原因、状态 | 追踪中 / 暂停 / 已移除，保留历史 |

店铺池属于空间配置（按空间隔离）。店铺和商品的观测数据仍是部署级共享，与现有设计一致。

### 2.2 eBay 店铺（官方接口，免费）

- **新品发现：**
  - 用 Browse `search`，条件为 `filter=sellers:{id}`，排序 `sort=newlyListed`，每天增量翻页，遇到已见过的商品即停。
  - 现有连接器已实现，**只差 eBay Production 凭据**。
- **出单：**
  - 用 `getItems` 快照。拿得到 `estimatedSoldQuantity` 就是 T1 已售量；
  - 拿不到就用可售量减少来推算（T4），补货当天记为缺失。
  - 这一点须用真凭据核验，见 `add-source-connectors` 1.1。
- **额度：** 30 个店铺约 1000 次/天，在 5000 硬上限、4500 安全线内。
- **兜底：** AIsa 的 eBay 搜索结果页接口（test 状态），只在官方凭据未到位时用于新品发现，层级记 T2。

### 2.3 Amazon 店铺（关键缺口）

Amazon 没有免费的官方"某卖家全部商品"接口。三个方案：

| 方案 | 新品发现 | 出单信号 | 覆盖率 | 成本 | 建议 |
|---|---|---|---|---|---|
| **A. Keepa**（现有连接器已实现，待订阅） | 卖家店铺 ASIN 列表，可按首次出现时间增量获取 | BSR 日历史、价格历史、卖家数历史 | 高 | 约 €49/月起 | **推荐**。BSR 历史也是 Amazon 历史回测的前提 |
| B. 仅用 AIsa（DataForSEO） | 用店铺品牌词和方向关键词搜索，再用 ASIN 详情确认卖家 | `bought_past_month`、评论数增量 | 中低（只能发现可被搜索到的新品） | 计入 §1.3 | 无 Keepa 时的过渡方案，数据中心标注覆盖率 |
| C. 自建网页抓取 | 店铺页 | 页面数据 | 高 | 低 | **不做**。违反平台条款且易被风控，数据稳定性差 |

推荐 **A + B 组合**：
- **Keepa** 负责"有什么、BSR 怎么走"；
- **AIsa** 负责"页面展示的销量区间、报价"。

两者互为交叉验证。

### 2.4 店铺级派生指标

| 指标 | 定义 |
|---|---|
| 上新速度 | 每周新品数 |
| 新品存活率 | 上架 30 天后仍在售的比例 |
| 新品命中率 | 上架 30 天内出现出单信号的比例：eBay 已售 ≥ 5，或 Amazon 进入 "50+ bought" |
| 店铺出单区间 | 店内商品出单区间之和，显示为区间 |
| 方向迁移 | 近 30 天新品的类目分布，与过去 90 天相比 |
| 同行扩散 | 同一商品簇在多个被追踪店铺中出现（已是算法维度，数据来源由此增强） |

**线索触发：** 被追踪店铺的新品在 14 天内出现出单信号 → 自动生成"店铺新品出单"线索，进入现有选品流水线。

## 3. 自有店铺：回验、漏斗与建议

### 3.1 接入

| 平台 | 自动接入（需开发者凭据） | 先行方案（立即可用） |
|---|---|---|
| Amazon | SP-API：Orders、**Sales and Traffic 报表**（会话、页面浏览、Buy Box 占比、订单商品数、转化率）、退货报表；**Ads API**（曝光、点击、花费、广告销售） | Seller Central 导出的"业务报告"和广告报表，用文件导入（框架已支持，增加预置模板） |
| eBay | Sell Analytics `traffic_report`（曝光、点击率、浏览、成交转化率）；Fulfillment 订单；Marketing 广告报表 | Seller Hub 导出的流量报告和订单报告，用文件导入 |

**建议先做文件导入，第一周就能看到漏斗。** API 接入等开发者审核通过后再做；数据模型相同，只是"获取方式"不同。

**隐私：** 自有店铺数据属于空间私有，必须用 `scoped()` 查询，**不进入**部署级共享观测表。用于校准的只是"误差统计"这类派生结果。

### 3.2 漏斗模型

```
曝光 ──CTR──▶ 点击/访问 ──CVR──▶ 订单 ──▶ 留存（未退货、无差评）
  │             │                 │
 搜索/广告      主图/标题/价格     详情/评论/价格/配送/Buy Box
```

- **粒度：** listing × 日。可按周、月，按方向、节点聚合。
- **每层都对照三个基准：**
  1. 自身历史中位数；
  2. 同方向自有 listing 的中位数；
  3. 竞品公开信号（价格、评论数、评分、出单区间）。
- **数据不全时，只算能算的层。** 例如没有广告报表，就不显示广告层，不估算。

### 3.3 回验（三件事）

1. **决策回验。** 对比决定跟卖时的预测（销量、售价、毛利、最晚决定日）与实际结果，计算达成率。结果回写选品档案库。现有设计中，30 天回看靠人工录入，这里改为**自动填充**。
2. **数据源校准。** 用自有商品的真实销量，检验 §0.3 中各来源的误差。
3. **算法回测。** 用真实结果打标签，权重高于影子推荐，用于更新命中率和准备度。

### 3.4 建议引擎

先用**可解释的规则**。AI 只负责把结论写成通顺的话，不参与判断。每条建议都附依据数据和置信度。

| 诊断 | 触发条件（默认，可调） | 建议方向 |
|---|---|---|
| 曝光不足 | 曝光低于基准 50% | 关键词、类目节点、广告预算 |
| 点击率低 | 曝光正常，CTR 低于基准 | 主图、标题、价格位置（附竞品价格分布） |
| 转化率低 | 访问正常，CVR 低于基准 | 详情页、评论数和评分差距、价格、配送时效、Buy Box |
| 退货或差评偏高 | 退货率、差评率高于基准 | 质量问题或描述不符，附差评原文 |
| 动销放缓 | 近 14 天销量较前 14 天下降 > 30%，且竞品未降 | 检查排名和价格竞争 |

面向未来的建议：

- **单品层面：** 补货、加投广告、降价清仓、放弃。补货量按销量趋势 × 采购和物流提前期计算，与核算的最晚决定日共用一套逻辑。
- **选品层面：** 统计过去真实结果中命中率最高的方向、店铺来源、节点类型，提高它们在线索排序中的权重。这样，自有结果直接反馈到选品算法。

## 4. 数据模型增量（概要）

| 变更 | 说明 |
|---|---|
| `observation` 增加 `tier`、`value_low`、`value_high`、`channel` | 分级、区间、经由渠道（aisa / direct） |
| `tracked_store`（按空间隔离）+ `store_listing`（部署级） | 店铺池；店铺 × 商品的首次、最近出现及下架时间 |
| `own_listing`、`own_daily_metrics`（按空间隔离） | 自有 listing 与每日漏斗指标（T0） |
| `source_calibration` | 来源 × 平台 × 类目 × 指标 → 样本量、误差、偏差、区间命中率、计算时间 |
| `accuracy_audit` | 人工抽检记录与一致率 |
| `import_templates` 预置 | Amazon 业务报告、广告报表；eBay 流量与订单报告 |

## 6. 需要你决定的事

1. **Keepa 是否订阅？** 它决定 Amazon 店铺追踪能否覆盖完整新品，以及是否有 BSR 历史。推荐订阅。
2. **月度预算上限。** AIsa 每月多少美元？建议起步 $150–300，同时在 AIsa 控制台给 key 设置同额硬上限。
3. **追踪规模。** 初始各追踪多少个 eBay 店铺、Amazon 店铺，热点 ASIN 上限多少？这决定成本。
4. **自有店铺。** 有哪些平台和站点、各几个店铺？能否先给一份 Seller Central 业务报告和 Seller Hub 流量报告的导出样例？SP-API 和 eBay 开发者账号是否要现在申请？
5. **评论正文。** 品类洞察的"差评痛点"需要评论正文，AIsa 目录里没有 Amazon 评论接口。可选：卖家精灵 / Helium 10 导出导入、P2 再找其他来源，或本期先不做痛点。
6. **Semrush。** 你提到它，但它只覆盖 Google 网页 SEO，对 Amazon/eBay 选品帮助有限。是否有具体用途（例如追踪独立站竞品）？没有的话本期不接。
7. **出单信号门槛。** 新品"开始出单"的默认定义是 eBay 已售 ≥ 5，或 Amazon 进入 "50+ bought"。是否合适？
8. **人工抽检。** 每周 20 个、约 10 分钟，是否接受？

**SerpApi 评估**

- **Amazon Product API**（2025-12 推出）一次调用就能返回三类数据：
  - `bought_last_month` 区间；
  - **BSR**（`best_sellers_rank`）；
  - 评论总数和星级分布，以及页面上的**评论正文**（`authors_reviews`，含标题、正文、星级、日期、是否 Verified）。

  不支持按星级筛选或翻页，条数以页面展示为准。
- **eBay Search**：可按卖家用户名筛选（`_sasl`）。但已不支持已售 / 已完成筛选，也没有已售数量字段，**不能替代 eBay 官方接口**。
- **价格**：免费档 250 次/月；Starter $25 / 1,000 次；Developer $75 / 5,000 次；Production $150 / 15,000 次。只有成功调用计数，缓存命中免费。
- **定位**：作为 Amazon 商品快照的第二来源，与 DataForSEO 交叉验证 `bought` 区间，并补上 BSR 和评论正文。测试规模下 100 个商品每天 1 次约 3,000 次/月，用 Developer 档。如果每 3 天一次，约 1,000 次/月，用 Starter 档就够。先用免费档验证字段。

**评论正文候选来源**

| 来源 | 方式 | 能拿到什么 | 成本与风险 |

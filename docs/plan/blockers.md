## D. 产品与算法默认值（已按默认实施，请审阅）

### D1 打分（packages/selection，M2）

- 冷启动时**硬门槛不通过仍显示“不推荐”**，只有门槛都通过时才用“未验证”替代等级（门槛是规则，不是统计）。
- 反向维度（竞争强度、供应与时效）分数越高表示越差，综合分取 100 − 分数。
- 季节：年际相关弱时把季节分向 50 收缩；只有 1 年数据时稳定性按 0.5 处理，置信度该项为空。
- Amazon 需求：月销量估算 ×0.7 + BSR（对数曲线）×0.3，暂无加速度项。
- 同行扩散：没有种子/已接受店铺或没有首次发现记录时为空；有记录但 14 天内没有对标店铺上新时为 0。
- 利润：未核算前平台费默认 eBay 13.6% + $0.40、Amazon 15%、退货预留 5%（M3 核算后改用核算结果）。
- 供应与时效：没有物流方案时用默认提前期 35/10/10/3 天，时间余量置信度减半。
- 合规：（已被 D1a 取代，流水线使用 packages/risk 的合规分）
- 所有常数集中在 `packages/selection/src/scales.ts` 的 `SCALES` 与 `confidence.ts` 的 `CONFIDENCE_SCALES`，是初始估计，需要用真实数据校准。
- “值得关注但证据不足”= 综合分 ≥ 75 且置信度低；算不出的置信度项不参与平均。
- 归并只在同一站点内进行；跨站点只按 GTIN 关联为簇属性。GTIN 去掉前导零后比较（UPC-12 与 EAN-13 视为同码）。

### D1a 每日流水线（packages/follow，M2）

- **合规分以 packages/risk 为准**（高 40、中 20、低 5，只有否决项否决），不用 selection 里“高风险即 0 分”的规则，否则所有非 Generic 品牌的同货源商品都会被否决。上面 D1 “合规”一条相应作废。
- 风险按线索的跟卖方式（`lead.follow_mode`）评估，新一天的线索沿用上一条的跟卖方式与改良参数；簇的风险取成员中最差的。
- 商品表没有属性列（带电、液体、儿童用品等），按属性匹配的风险规则目前只能靠类目命中。需要的话加商品属性来源。
- 没有设置类目、卖家或关键词的方向不选任何商品；每个方向每次最多读取 5000 个商品；关键词按标题模糊匹配。
- 新一天的线索沿用该簇上一条线索的状态；同一天重跑不覆盖人工改过的状态。
- 核算组合挂在线索上：上一条为核算中 / 待决定时，新一天的线索复制其全部组合（保留选定与结果快照，`result.copiedFrom` 记来源线索与组合）；已跟卖 / 已放弃的簇只继承状态。核算标签、选定、跟卖 / 放弃都解析到簇的最新线索，待决定队列与候选数只看最新线索，簇的任一线索已有决定即锁定核算。
- 利润与供应时效取该簇最近一条有可用核算组合的线索（已选定的优先，否则毛利率最高的）；没有核算时利润为空、毛利门槛不判。准备度在样本积累前为冷启动。

### D0 每日采集计划（M1a 3.2）

- 步骤按队列延迟串联（02:10 卖家新品、02:30 快照与关键词），不是多步 Workflow；每个任务独立预扣、重试、死信，重启后靠任务幂等键不重复投递。当天 02:10 扫到的新品要到 04:00 归并后才进入次日的快照。
- **Keepa 是每分钟 20 token**：每批最多 20 个 ASIN，铺在 02:30–03:30 的 60 个分钟槽里，超出部分顺延到次日。Amazon 商品多时 Keepa 是瓶颈，可能需要更高的 Keepa 套餐。
- 按安全线严格截断：某数据源排不下一个任务后，其后更小的任务也一起顺延。
- eBay 卖家扫描每个类目一个任务，没有类目时用关键词，二者都没有则不扫；只扫第一页（200 条），未做翻页。
- DataForSEO 每周一运行，季节曲线每个关键词单独请求（避免互相归一化），搜索量每批最多 1000 个关键词。
- 模拟数据源不进入每日计划。

### D1b 选品方向与设置（M2 表与页面）

- 预置节点与默认评分设置在首次进入方向/设置页时写入，判断依据是“评分设置 v1 是否存在”：**团队删光预置节点后不会再自动补回**（spec 原文是“没有任何节点时插入”，可改）。
- 黑五、母亲节、Prime Day 等按“第几个星期几”的节日用近似日期，页面提示每年核对。
- 已有商品簇的方向不能删除，只能停用；删除节点会从所有方向的关联中移除。
- 已拒绝的推荐店铺保留记录（不再推荐）；移除种子/已接受店铺会删除记录，之后可能再次被推荐。

### D2 风险（packages/risk，M2）

- 扣分：高 40、中 20、低 5、提示 0；任一否决时合规分为 0。
- VeRO 命中在“同款微改良”方式下**同样否决**；品牌备案只在 Amazon “在他人现有 ASIN 下直接跟卖”时否决（同货源默认是，微改良默认否）。如果你希望 VeRO 对微改良降级为提示，需要改一处判断。
- 品牌属性非 Unbranded/Generic 即记品牌风险（同货源高、微改良中），不否决。

### D3 核算（packages/costing，M3）

- 微改良建模为“单价加成率 + 一次性改款费（按计划数量分摊）+ 打样天数”。设计稿公式把改款费同时写在采购与落地成本里，这里拆开理解，请确认。
- 毛利率 = 净利润 ÷ 售价；保本价向上取整到 1 美分。
- 首重续重方案配了体积重系数但报价缺尺寸时，按实重计费并降低成本确定性（0.5），不算缺输入；按方计费缺尺寸则视为缺输入。
- 没有显式 MOQ 时以最低阶梯数量为 MOQ。
- 没有关联节点时不算最晚决定日，也不判“来不及”。
- 成本瀑布 7 步：仓储与 FBA 入库配置费并入“配送/尾程”，改款费分摊并入“采购”。

### D3c 报价与核算矩阵（M3）

- **FBA 配送费暂时手填**：SP-API 与费率表都还没有来源，矩阵工具栏有“FBA 配送费（费率表）”输入框，不填时 FBA 组合显示“缺少：FBA 配送费”。SP-API 凭据到位后接入费用预估。
- **商品属性（带电/液体等）在矩阵工具栏手填**，只保存在选定组合的快照里；商品表没有属性来源（与 D1a 同一个缺口）。
- 从品类洞察转来的“微改良”线索只带改良说明，需要在核算标签里补填单价加成率、改款费、打样天数后才能计算。
- 汇率按 `币种/CNY` 主值经人民币交叉换算，矩阵上方列出所用汇率、日期与来源。
- 计划数量默认：已选组合的数量 → 报价最小 MOQ → 100；竞品中位价取簇成员近 30 天最新价格（最常见币种）。
- 线索在第一次写入核算（录入/导入报价、切换跟卖方式、保存改良参数）时进入“核算中”；只打开标签不改状态。
- 簇的最新线索已决定后，该簇的报价不能再增删改或导入；被已选组合或已决定线索引用的报价不能删除。
- 设置页“成本参数”新增表单默认平台是 Amazon，给 eBay 配参数需手动切换（验收时碰到，属于体验问题，未改）。

### D3a 决定与档案库（M3）

- **只有 owner/admin 能做跟卖/放弃决定和录入回看**，普通成员只读。团队共用一个账号时没有影响；如果以后有成员账号且需要能决定，改一处检查。
- 放弃可以在 new / costing / pending 任一状态做；跟卖要求已选定核算组合。放弃原因选“其他”时必须填说明。
- 工作台 KPI：“候选线索”按商品簇去重计数；“本周”从新加坡时间周一 0 点算；“数据源今日额度”取各数据源当日用量占比的最大值。
- 档案库最多列 200 条；重复录入回看会覆盖上一次；实际毛利率按原组合费率随售价线性估算。
- 30 天回看提醒发给做决定的人（已离开空间则发给 owner/admin），每条决定只提醒一次。

### D3b 品类洞察（M4）

- **AI 用量走模板的对话计费路径**：每次分析会在 AI 对话列表里留下一条名为“品类洞察 · <研究名>：差评痛点与差异化建议”的对话，并按积分预扣结算。模型取空间套餐允许的第一个启用文本模型，没有单独设置。评论与竞品没变时刷新复用上次结果，不重复计费。
- 生成/刷新时有差评且有可用模型就自动调用 AI；没有评论或没有模型时显示原因、不调用。
- 研究覆盖范围：所选站点中类目命中或标题含关键词的商品，最多 2000 个。
- **退货率恒为“无数据来源”**：没有任何数据源提供退货率，也没有用成本参数里的退货预留率代替。
- 集中度的“交叉验证”判断：任一商品当天的销量估算有第二个来源即视为已交叉验证。
- 评论数据来源仍未确定（见 C）；没有评论时差评痛点与差异化建议都显示“无数据来源”。

### D4 验证（packages/selection labels/readiness/fit，M5）

- 打标签时**价格也算关键观测**：缺冻结日前的基准价，或窗口内价格缺失超过一半，都标“数据不足”。价格数据稀疏时标签会偏严。
- 销量增量 = 观测到的日均销量 × 窗口天数；缺失恰好一半仍可打标签。
- 准备度：有效样本 ≥ 50 但基线未知时停在“观察期”；“可信”的稳定性看计算日前最近 3 个完整月，任一月有效样本 < 5 视为不稳定。
- 历史命中率置信度：样本 < 20 时为空，并把总置信度乘以 0.9（“降低总置信度”的具体系数是自定的）。
- 权重拟合：L2=0.1 的逻辑回归、分层 5 折；命中或未命中少于 5 个、或没有任何维度与命中正相关时拒绝拟合；建议权重按“每分效应”换算、负值截为 0、总和对齐当前设置。提升度 = 预测概率前 20% 的命中率 − 总体命中率。

### D4a 影子验证流水线（packages/follow，M5）

- **命中标准 X / Y / 高峰误差目前只有代码默认值**（30 件 / 15% / 2 周），还没有页面设置；定时任务一律用默认值。需要的话加到数据中心评分维度管理里。
- 基线（同方向随机新品命中率）每周按确定性哈希抽最多 50 个新品，在内存中打标签，只保存命中率，不保存样本明细。有效基线样本少于 5 个时基线为空，准备度最高停在“观察期”。
- Keepa 回放的状态记在 `sync_run`（父任务一行 + 每批一行），没有单独建表；回放用当前评分设置和当前风险名单、复用现有商品簇；额度不足时无限次顺延。
- 置信度现在总是包含“历史命中率”项：无统计时为空并 ×0.9，所以已有线索的置信度会整体略降。
- 为了给回放打标签，Keepa 连接器新增解析 `monthlySoldHistory` / `monthlySold` 为月销量估算（获取方式“估算”），需要用真实 Keepa 响应核验字段。
- 数据不足的标签视为最终结果，之后补到数据也不重打。

### D5 导入

- Excel 解析选用 `read-excel-file` 9.3.10（MIT，体积小，数字保留原文本）；不支持旧版 `.xls`。文件上限 5 MB；压缩炸弹（解压后极大）暂未单独限制。

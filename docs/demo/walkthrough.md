# 团队试用走查

本轮验证的是业务工作流是否可理解、数据能否追溯。客户效率与经营效果尚未验证。

## 准备

启动前后端，打开工作台。空库需明确点击初始化样例。演示时钟固定为 2026-09-20 08:00 UTC；页面、证据与 AI 输出分别标明样例/模拟。不要把模拟结果当市场事实。

## 走查顺序

1. 选品负责人建立渠道项目，说明目标、约束、责任人；决策负责人确认硬规则与必填证据。
2. 分别尝试露营方向发现与 CSV 导入。说明哪些是原始定位、哪些是待核验资料。
3. 打开候选，区分已核验事实、估算、假设；缺失/过期/冲突只补证，不直接判定失败。核验 MOQ 超标时记录排除原因；确有例外需负责人说明。
4. 用模拟整理生成评估草稿，逐项核对五维结论、引用、未知与反证。保存评估版本后提交。
5. 切换决策负责人，退回一个问题。分析负责人补充材料、保存新评估并重提；再批准。检查所审快照和结果跟进义务。
6. 新建询价、样品或小测任务，填写负责人、期限与完成条件。结果未达目标仍可记录任务完成；是否继续由负责人决定。
7. 转入结果跟进。记录实际窗口、币种、收入口径及成本；未知字段留空。停止未上市需明确原因，不能填虚构零销售。
8. 查看预测与实际差异，记录复盘。提出下一轮标准调整，负责人确认或拒绝，再将确认版本用于新项目。原批准快照必须保持不变。

## 每轮记录

- 哪一步需要解释，用户是否理解“下一步”和“由谁处理”？
- 数据来自哪里，核验、补证、纠错分别花多少分钟？在工作台记录工时和试用意见。
- 哪些字段已有日常报表支持？哪些需要新增采集？真实数据授权、可得性和成本是什么？
- 记录同一类业务的人工基线，至少能比较完整周期与核验/纠错成本；没有基线不报告效率百分比。
- 经营结果需跨足够观察窗口验证；团队使用意愿、接口数据质量、节省时间和选品收益分别确认。

## 重置

重置会清除当前本地数据库的业务与试用记录，恢复相同版本样例。需展开重置区域并明确确认，版本过期应刷新重试。其他数据库及研究文档不受影响。保留试用记录时先备份当前 SQLite 文件。

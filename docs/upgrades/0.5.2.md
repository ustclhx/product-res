## 概要

- **对话入口与浮动控件避让**（#373，解决 0.5.1 已知问题）：
  - 路由可用 `staticData: { floatingControls: false }` 关闭根布局的浮动语言 / 主题控件，模板的对话详情页已关闭；
  - 桌面端存在浮动控件时，`<body>` 带 `data-floating-controls`，并设置 CSS 变量 `--floating-controls-offset`（3rem）；
    `EmbeddedChat` 的触发器叠在浮动主题切换上方，不再重叠。项目自己的右下浮动按钮可同样使用该变量。
- **预计消耗扩展点**：新增项目自有文件 `apps/web/src/features/ai/chat-composer.project.tsx`，导出
  `ProjectComposerEstimate`（默认 `undefined`，使用模板的积分预计文案）。项目需要按自己的计价展示预计消耗时，在该文件导出组件即可，模板同步不覆盖。
- **e2e 夹具可配置**：`seedChatModel` 的 Provider 可通过参数或 `E2E_CHAT_PROVIDER` 指定；`newConversation` 等待「New chat」出现后再继续。
- **本地 dev 排除 `/e2e/*`**：`wrangler.jsonc` 的 `run_worker_first` 增加 `!/e2e/*`，嵌入式对话 e2e 的测试模块由 Vite 直接提供，不被项目站点守卫拦下；生产无影响。
- **多站点文档**：`docs/share-cards.md` §6.1 与 `docs/design-system.md` §9.3 改为按 host 判断站点，不按语言判断。
- **提前停止生成**（#362）：在收到流式响应的 start 之前点「停止」，客户端也会调用新接口 `POST /api/ai/chat/stop`
  （`{ slug, conversationId, requestId }`），服务端停止生成并按停止结算；每条消息带客户端 `requestId`。无数据库迁移。
- 修复：`waitHealthy` 单次请求时限可与轮询间隔分开（`requestTimeoutMs`），修复冷启动时 health 用例偶发失败（#212）；
  e2e 适配 0.5.1 手机端页脚控件，billing-actions 用例结束前撤掉路由拦截（#334）。
- OpenSpec `add-billing-coexistence` 已在 staging 用 Stripe 测试模式完成订阅与积分包购买验收并归档。

## 已知问题

- **跨实例提前停止**：停止请求落到另一 Worker 实例、且生成在约 6 秒内未写入回复记录时，该回复仍会生成并计费（#383 说明）。
- **自定义发送逻辑**：项目不经模板的 `features/ai/conversation.ts` 发送消息时，需要自行在请求体带上 `requestId` 才能使用提前停止。

## 概要

处理 0.5.10 的已知问题，并采纳衍生项目对语言建议横幅的三条反馈。

- **Android 上的 Inter 度量匹配回退字体**：Android 没有 Arial，0.5.10 的 `"Inter Fallback"` 在 Android 上不生效。
  字体栈改为 `"Inter Variable", "Inter Fallback", "Inter Fallback Roboto", …`。新的一组用本地 Roboto，
  按 Inter 的宽度缩放（常规 106%、粗体 103%），纵向度量同样取 Inter 的 1984 / 494 / 2048 除以 size-adjust。
  有 Arial 的平台上拉丁字符已由 `"Inter Fallback"` 覆盖，这一组不会被用到。
  Chromium 中统计营销页英文文案 322 段与 Inter 换行不同的段落数，未缩放 → 缩放后：
  - 16px 正文、343 宽：34 → 3；
  - 30px 粗体标题：41 → 8；
  - 其余字号与宽度同样下降，与 Arial 一档持平。
  未在 Android 真机验证。`local("Roboto")` 匹配不到时规则不生效，行为与 0.5.10 相同。
- **水合前切换语言保留查询参数与锚点**：首帧脚本在「切换」时把 `location.search + location.hash` 补到链接上，
  例如 `/pricing?utm_source=x` → `/zh/pricing?utm_source=x`。水合后的路径本来就保留。
- **语言建议横幅不进入搜索摘要**：横幅内容包在 `<div data-nosnippet class="contents">` 中，版面不变。
- **语言匹配支持书写系统**：首帧脚本的匹配顺序改为完整标签 → 补全后的「语言-书写系统」（`Intl.Locale.maximize()`）→ 主语言子标签。
  配置 `zh-Hant` / `zh-Hans` 的项目无需别名：`zh-TW` / `zh-HK` 匹配 `zh-Hant`，`zh-CN` / `zh-SG` / `zh` 匹配 `zh-Hans`。
  只配置 `zh` 时结果与此前相同。
- **可建议语言**：新增 `SUGGESTABLE_LOCALES`（`apps/web/src/features/i18n/suggestion.ts`，默认 `undefined`，即全部非默认语言）。
  首帧脚本与所有 `LanguageControls` 实例默认读取它；也可分别传入同名参数 `suggestableLocales`（两处须一致）。
  浏览器偏好中最先匹配到的语言不在其中时不建议，不再往后找，也不写 `<html>` 属性。
- **测试不再依赖浮动语言下拉与 `/zh`**：横幅水合后带 `data-hydrated` 属性（只有属性，无样式），e2e 以它判断水合完成；
  目标语言取自 `template.config.ts` 与 `SUGGESTABLE_LOCALES`，期望地址读自横幅链接。没有可建议语言时跳过并写明原因。

## 配置变更

无。说明：

- 只需建议部分语言（如多站项目）时，修改 `SUGGESTABLE_LOCALES`。
  按站点在运行时决定时，把同一个值同时传给根路由的 `localeSuggestionScript` 与 `LanguageControls` 的 `suggestableLocales`。
- 项目自己写过语言别名映射（如 `zh-TW → zh-Hant`）时，可以删掉，改用内置的书写系统匹配。

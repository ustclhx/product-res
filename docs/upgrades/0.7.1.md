## 概要

修正 product-res 同步 0.7.0 时 CI 暴露的问题，以及两处偶发失败。

- **营销页关闭时构建失败**（#421）：`marketing.enabled=false` 的项目不预渲染页面，`inline-critical-css` 与 `check-home-bundle` 却按有预渲染产物处理，`pnpm build` 必定失败。
  - 构建时把本次是否预渲染写入 `dist/.build/marketing-performance.json`。这两个步骤读到 `prerender: false` 时，打印说明后跳过。
  - 启用预渲染却找不到 HTML 时，仍然报错。
  - Nightly 对全部功能关闭的生成副本加跑一次 web 生产构建。
- **template-sync 验证补齐**（#421）：在 typecheck 之前加 `pnpm dedupe --check`，在测试之后加 `pnpm build`，与 CI 的 lint、build job 一致。此前同步报告全部通过的分支，到 CI 仍可能失败。
- **jobs 测试偶发失败**（#422）：串行执行时，前面的 `node-production` 用例若跨过 `*/5` 心跳整点，会在同一个库写下 `jobs.lastCronAt`，使 `node-wire` 首次 ready 得到 200 而不是 503。现在 `node-wire` 启动前先清除这个键。
- **`install-chromium` 超时留下占锁进程**（#423）：
  - 原因：timeout 以 runner 用户运行，超时时只能结束 pnpm，经 sudo 启动的 apt-get 仍持有 dpkg 锁，后续重试全部失败。
  - 现在系统依赖由 root 的 timeout 直接运行 playwright CLI 安装，超时会结束整个进程组。
  - 重试前清理残留进程，并等待锁释放。
  - email 的 `import-boundary` 用例超时放宽到 30 秒。

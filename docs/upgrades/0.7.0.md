## 概要

采纳 xuanxue 与 product-res 同步 0.6.0 时的反馈：补上 CI 中从未运行的数据库测试，防止测试改动开发库，并修正生成器与同步工具的问题。

不兼容点：没有隔离库时，本地 `pnpm test` 不再回落到开发库，而是直接报错（见「必须执行的动作」1）。

- **补上 CI 中被静默跳过的数据库测试**（#417）：
  - strict env 模式过滤掉了未声明的数据库连接串，这些包的 Postgres 测试一直没有在 CI 中运行：
    - credits：0 → 70 项；
    - billing：233 → 335 项；
    - storage：7 → 34 项；
    - entitlements：15 → 17 项。
  - 新启用的测试全部通过。
  - 以上各包的 `test` 任务已设 `cache: false` 并 passThrough 连接串。
  - `scripts/check-turbo-inputs.mjs`（在 `pnpm check` 内）新增检查：vitest 配置读取的环境变量若未在 turbo 中声明，直接报错。
- **生成文件随缓存恢复**（#417）：web 的 `typecheck` 与 `build` 把 `.content-collections/generated`、`routeTree.gen.ts`、`paraglide` 声明为 outputs。
  缓存命中后，读取这些生成内容的后续检查不再缺文件。
- **测试不再迁移开发库**（#419）：
  - 新的 `@product-res/db/test-database` 只允许在隔离库上测试，库名须为 `<前缀>_wt_<名>`、`<前缀>_test[_<名>]`，或 CI 中的 `<前缀>_ci`。
  - 非隔离库会在连接之前报错，并给出建隔离库的中文说明。
  - 没有任何数据库配置时，db、auth、jobs、web 在本地直接报错（此前会回落到 `<name>_dev` 并执行迁移），CI 中照旧跳过。
  - 确需在开发库上跑测试时，显式设置 `ALLOW_TEST_ON_DEV_DATABASE=1`。
  - `global-setup` 在执行迁移前也会做同样的检查。
- **生成器**（#418）：
  - `*.project.ts(x)` 首次生成时也会改 scope；
  - 生成后与同步参照副本都会用锁定版本的 Biome 格式化；
  - check-ui 的生成器用例在衍生项目中跳过，测试用的白名单写入临时目录。
- **storage 桶名**（#419）：`presign.ts` 导出 `FILES_BUCKETS`，测试从这里取桶名，不再写死 `'files'`。此前改名后衍生项目的 6 个用例会失败。
- **同步工具**：
  - `infer-base` 增加 `--generation-commit`，用于合并进已有仓库、存在多个根提交的项目（#415）；
  - 二进制差异单独计数，不再算作 Infinity（#415）；
  - `--write` 配合 `--force` 可以越过阈值，并输出警告（#415）；
  - `--param domain` 接受不带协议的域名（#415）；
  - 支持本地 `--filter=blob:none` 部分克隆作为 `--template`（#416）。
- **CI**：
  - staging、production 部署与 disabled-features 改用 `install-chromium`，衍生项目实测 staging 部署快约 5 分钟（#416）；
  - `install-chromium` 安装前先停掉 apt-daily 与 unattended-upgrades，并等待 dpkg 锁释放（#419）；
  - 项目可以用 `.github/ci-docs-paths.json` 追加纯文档目录，代码目录会被忽略（#416）；
  - `docs/ci.md` §4 补充：部署流水线固定分组时，排队中的 run 会被更新的 run 替换。
- **更正 0.6.0 说明**：`selfhost-features.yml` 只存在于模板仓库，生成的项目中没有。同步时列为「模板已删除」，按删除处理即可。

## 必须执行的动作

1. 在没有 `.env.worktree` 的目录（主 checkout、普通 `git worktree`）运行 `pnpm test` 之前，先准备隔离库：
   在 Orca worktree 中运行，或按报错提示创建 `<前缀>_wt_<名>` 库并写入 `.env.worktree`。
   确需在开发库上运行时，设置 `ALLOW_TEST_ON_DEV_DATABASE=1`。
2. 同步后运行 `pnpm check`，按 `check-turbo-inputs` 的提示为项目包的 `test` 任务补齐 `passThroughEnv`；依赖数据库的测试设 `"cache": false`。
3. 已经自行修复 storage 测试桶名（如改成 `<name>-files`）的项目，改为使用 `FILES_BUCKETS[0]`，避免以后再次对不上。

## 配置变更

无新增密钥或部署绑定。新增可选环境变量 `ALLOW_TEST_ON_DEV_DATABASE`（仅测试用），以及可选的项目文件 `.github/ci-docs-paths.json`。

## 验证

```sh
pnpm check
pnpm test   # 在 Orca worktree 或已配置隔离库的目录中
node --test 项目维护约定 scripts/ci/plan.test.mjs scripts/check-turbo-inputs.test.mjs
```

1. CI 的 `test-packages` 日志中能看到 billing、credits、storage 的集成测试在运行。
2. 移走 `.env.worktree` 后，在本地运行 `@product-res/db` 的测试应直接报错，提示「不会回退到开发库」。

## 回滚

回退本版本代码即可。回退后，测试会重新回落到开发库，请注意。

## 已知问题

- apt 锁的处理只有在新 runner 恰好遇到 apt-daily 时才能真正验证。
- 部分测试文件与 e2e 代码中仍有各自的 `product_res_wt_` 检查。它们只会更严格，迁移已由配置与 `global-setup` 拦截。
- 从很旧的基准首次同步时，生成器新加的统一格式化可能与项目自己的修改重叠，需要人工合并。

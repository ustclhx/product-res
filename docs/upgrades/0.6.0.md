## 概要

CI 提速与降本，并停止构建与发布 arm64 自托管镜像。规则写入新的 [CI 规范](../ci.md)，`AGENTS.md` 增加指向。

不兼容点：自托管只发布 linux/amd64，`init-server.py` 拒绝 arm64 主机。

模板实测（2026-11-18/19，与此前 30 天中位数对比）：

| 环节 | 之前 | 现在 |
| --- | --- | --- |
| PR 的 CI | 8.1 min | 4.0 min |
| 纯文档 PR | 8.1 min | 1.7 min |
| PR 的 `Selfhost images` | 约 18 min，每个 PR 都跑，双架构 | 约 13.5 min，仅相关路径变更时运行，单架构 |
| 合并 → staging | 约 10 min（main 上重跑全部 CI） | 约 3 min（复用 PR 结果） |

- **CI 三种模式**（`scripts/ci/plan.mjs`，`ci.yml` 的 `changes` job）：
  - `docs`：纯文档改动只跑 `lint`；
  - `reuse`：main 上的提交树与其 PR 已成功全量测过的合并树相同时，跳过重复测试，直接触发 staging；
  - `full`：其他情况。
  无法判断时一律 `full`。判断条件见 CI 规范 §2。
- **任务拆分**：原 `check`、`node` 拆为 `lint`、`build`、`test-packages`、`test-web`、`node-web`、`node-jobs`、`node-build` 并行。
  新增两个 composite action：`.github/actions/setup-workspace`、`.github/actions/install-chromium`。
- **Turbo 缓存**：`build` 与 `test-packages` 使用 Turbo 本地缓存，依赖数据库的测试不缓存。
  - 新增 `scripts/check-turbo-inputs.mjs`（并入 `pnpm check`），检查包内源码引用的包外文件是否在任务 `inputs` 中。
  - 据此补全根 `globalDependencies` 与 web、jobs、db、entitlements 的 `turbo.json`。本地增量缓存也因此更准确。
- **`node-build` 在冒烟前执行迁移**：先跑 `db:migrate` 与 `dbos:migrate`。此前依赖同一 job 里先跑的测试完成迁移。
- **并发**：PR 上的新推送取消旧运行。main 与发布调用按 SHA / `run_id` 分组，不再被取消；此前被取消的 main CI 会让该 SHA 无法部署。
- **自托管镜像**：
  - 只构建 linux/amd64，改用 runner 默认 docker driver；`type=gha` 层缓存实测更慢，未采用；
  - PR 与 main 只上传证据 JSON，镜像 tar 只在发布时上传；
  - `Selfhost disabled features` 在 PR 上按路径触发；
  - `bundle.py` 新发布只要求 linux/amd64，仍接受已发布的双平台版本，旧版本可回滚；
  - 本机 Apple Silicon 仍可构建 arm64 镜像做开发测试。

## 必须执行的动作

1. 同步 CI 文件：
   - `.github/workflows/ci.yml`、`template-release-checks.yml`、`selfhost-images.yml`、`selfhost-features.yml`；
   - `.github/actions/`（新增 `setup-workspace`、`install-chromium`，`prepare-local-tests` 有修改）；
   - `scripts/ci/`、`scripts/check-turbo-inputs.mjs`、根 `package.json` 的 `check` 脚本、各 `turbo.json`。
   项目改过这些文件时，三方合并后保留项目自己的步骤，并按 CI 规范 §3 放入对应 job。
   项目的 workflow 自行安装 Playwright 时，改用 `install-chromium`。
2. 运行 `pnpm check`。`check-turbo-inputs` 报出项目包引用的包外文件时，把它加入该包 `turbo.json` 的任务 `inputs`，
   或加入根 `globalDependencies`。依赖数据库的项目测试设 `"cache": false`。
3. 自托管部署在 arm64 主机上的项目：先迁到 linux/amd64 主机再升级。新版本只发布 amd64 镜像，`init-server.py` 会拒绝 arm64 主机。
   不使用自托管的项目跳过此项。
4. 项目自有的 workflow 按 CI 规范 §4 补 `concurrency`：PR 取消旧运行，main 不取消。

## 验证

```sh
pnpm check
node --test scripts/ci/plan.test.mjs scripts/check-turbo-inputs.test.mjs
```

1. 开一个只改 `docs/` 的 PR：CI 约 2 分钟内成功，只运行 `changes` 与 `lint`。
2. 合并一个普通 PR，且合并前 main 没有新提交：main 的 CI 只运行 `changes` 并成功，随后 staging 部署成功。
3. 手动运行 CI 并填写 `probe_sha`，可在日志中查看某个提交的复用判断。

## 回滚

回退本版本代码即可。

已发布的双平台 release 仍可部署。回退后，新发布会恢复为双平台构建。

## 已知问题

- `node-jobs` 与镜像冒烟都要等真实的 5 分钟 cron 心跳，耗时在 1.5–5 分钟之间波动。
- 首次以单平台发布镜像时，需核对 image-set 的 `platforms` 为 `["linux/amd64"]`。
- `selfhost-release-acceptance.yml` 固定的发布运行，其 artifact 已超过保留期，这个 workflow 无法通过，需单独修复。
  它只在自身或 `test-release-compose.py` 变更时触发。
- billing 与 credits 的 Postgres 测试不在 `turbo run test` 中运行：strict env 隐藏了数据库连接串。
  billing 由 web 的 `test:node` 覆盖，credits 的覆盖待确认。此问题在本版之前就存在。

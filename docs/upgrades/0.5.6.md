## 概要

首页水合不再下载 zod，并处理衍生项目采纳 0.5.5 时反馈的三个工具问题。

- **zod 的真正入口是路由树分包**：TanStack Start 的水合入口会立即 `import()` StartClient 与整棵路由树（`client-*.js`），
  路由定义中不随组件拆分的部分（`validateSearch`、`?tsr-shared` 共享常量）与它们静态引用的模块都在这里，每个页面水合都会下载。
  模板此前的首页包检查只看静态闭包，没看到这一层；路由多的项目分包结果不同，路由树直接进了静态闭包，才报出 zod。本版：
  - 客户端构建把 zod 链式调用视为无副作用（新增 `apps/web/scripts/client-pure-schemas.ts`，经 `vite-shared` 接入，
    Rolldown `treeshake.manualPureFunctions: ['z']`）。TanStack Start 在客户端删除 server function 的 validator 调用后，
    模块顶层没人引用的 schema 随之摇掉——项目自己的 `*.functions.ts` 不用改；
  - 模板路由的 `validateSearch` 改用新的 `apps/web/src/features/routing/search.ts`（`optionalString`、`optionalEnum`、`requiredUuid`），
    不再用 zod：登录、注册邮件回跳、重置密码、验证邮箱、账户、接受邀请、支付回跳；
  - `packages/config/src/node-schema.ts` 的基础 schema 用纯标注的立即调用函数包裹（参数里有 `secret.optional()`，打包器判断不了）。
  - 模板示例：路由树分包不再引用 zod；首页静态闭包 gzip 204660 → 204650 B，水合闭包 gzip 276043 B（此前含 zod 约 35KB）。
- **首页包检查**（`check-home-bundle.mjs`）：zod 检查改看「水合闭包」（静态闭包加上水合入口直接 `import()` 的分包），
  发现时按 sourcemap 列出引用 zod 的源文件与修正方法；通过时另输出水合闭包的脚本数与 gzip。预算仍按静态闭包计算，含义不变。
- **`check-critical-css.mjs`**：页面 HTML 改经 Chromium 获取（Node 的 fetch 解析 `*.localhost` 走系统 DNS，fake-IP 代理下会失败）；
  截图文件名保留各语言字母与数字并解码百分号编码，CJK 路径不再塌缩成同名互相覆盖。
- **`template-sync sync --trailer "<键>: <值>"`**（可重复）：给两个同步提交追加项目约定的尾注（如 `Co-Authored-By`），不必事后 amend。

## 配置变更

无。升级后 `pnpm build`，若仍出现「首页水合闭包 … 有 zod schema 实现」警告，按警告下列出的源文件处理：

1. 项目路由的 `validateSearch` 用 zod 的，改成：

   ```ts
   import { optionalString } from '../../features/routing/search.ts'

   validateSearch: (search: Record<string, unknown>) => ({ tab: optionalString(search.tab) }),
   ```

2. 路由文件或 `?tsr-shared` 部分（同时被路由定义和页面组件引用的常量）在模块顶层用 zod 做运行时校验的，移到页面组件或服务端模块。
3. 模块顶层 schema 的参数里调用了 schema 变量的方法（`base.optional()`、`shared.extend(...)`），用 `/* @__PURE__ */ (() => …)()` 包裹。

客户端构建会删除结果不被引用的 zod 调用：项目若在模块顶层只为副作用调用 zod（`z.config(z.locales.xx())`、`schema.register(…)`）且需要在浏览器生效，改为在会被调用的函数里执行。服务端构建不受影响。

警告消失后，按「首页包检查通过：… gzip 合计 N B」加约 5% 设置 `homeScriptGzipBudget`。

## 概要

处理 xuanxue 同步 0.7.0 后的反馈：测试库回落、template-sync 纯格式冲突，以及一处偶发超时。

- **测试库本地回落到 `<项目>_test`**（#425）：
  - 起因：0.7.0 起，主 checkout 没有 `.env.worktree` 时 `pnpm test` 直接报错，衍生项目只能自己包装 `resolveTestDatabase`。
  - 未配置连接串、不在 CI、且测试配置启用了 `devFallback` 时，改用 `<项目>_test`，并打印所用的库。库不存在时，`globalSetup` 给出建库与授权命令。
  - 连接的主机与端口从项目的本地开发配置推导，依次读取 `apps/web/.dev.vars`、根目录 `.env`、`infra/local/docker-compose.yml`，不再写死 `localhost:5432`。
  - CI 行为与 `ALLOW_TEST_ON_DEV_DATABASE=1` 的语义不变。
  - 项目自身的隔离验证 只在 linked worktree 中运行，主 checkout 中直接退出。此前在主 checkout 运行它会写出 `.env.worktree`，使开发服务器从 dev 库切到 `wt_*` 库。
  - 用法见 [项目结构 §5](../02-project-structure.md#5-本地集成测试数据库)。
- **template-sync 消除纯格式冲突**（#426）：
  - 起因：基准副本由旧版本生成器生成，没有 0.7.0 新增的 Biome 格式化与 Wrangler 占位 ID 编号，同步时产生大量只差格式的冲突。
  - 现在基准与目标两份副本合并前执行同一套目标版本的后处理。项目文件仍与旧生成结果逐字节一致时，以原始基准应用模板变更。
  - `infer-base` 用同样的规则归一化后再计分。
  - 在 xuanxue 的只读副本上回放 0.7.0 同步，冲突从 66 个降到 19 个。
- **启动真实 Node 进程的测试偶发超时**：CI 负载下超过 vitest 默认的 5 秒。jobs 的 `node-build`、`node-load` 放宽到 60 秒；platform、storage、config 中启动 Node 子进程的用例放宽到 30 秒。
- **勘误**：0.7.0 升级说明中「补上被静默跳过的数据库测试」列出的是模板仓库自身的测试数，衍生项目的增量不同。

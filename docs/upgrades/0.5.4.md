## 概要

营销页首屏关键路径（OpenSpec `add-marketing-critical-path`）。Lighthouse 移动端 simulate 估算的 LCP 约与首帧前下载的字节数成正比，
本版把首帧前不需要的字节移到首帧之后。模板示例三次中位数（`lighthouse@13.5.0`，`vite preview`）：

| 页面 | LCP 前 → 后 | FCP 前 → 后 | TBT 前 → 后 | CLS 前 → 后 | 首帧前完成的请求 |
| --- | --- | --- | --- | --- | --- |
| `/` | 6.64s → 1.81s | 5.43s → 1.11s | 66 → 64ms | 0.1195 → 0.1179 | 936KB → 174KB（其中 JS 683KB → 0） |
| `/zh` | 7.52s → 1.81s | 5.86s → 1.14s | 20 → 50ms | 0 → 0 | 1070KB → 173KB |
| `/pricing`（动态渲染，未改） | 6.51s → 6.48s | — | — | 不变 | — |

首页 HTML 185KB → 102KB（内联 CSS 124KB → 42KB），首页客户端闭包 gzip 242KB → 208KB。三次测量之间的波动也随之消失（1.66–1.82s）。

- **字体预加载扩展点**：新增项目自有文件 `apps/web/src/features/theme/fonts.project.ts`，`projectFontPreloads(defaults)` 默认原样返回模板的
  Inter 预加载；`@product-res/ui/fonts` 新导出类型 `FontPreload`。`brand.css` 覆盖了 `--font-sans` 而首页仍预加载 Inter 时，`pnpm build` 打印警告。
- **客户端不再解析模板配置**：客户端环境加载 `template.config.ts` 时由构建期解析好的 JSON 代替（服务端照常执行与校验），
  `security-client.ts` 只导入 zod 的 `config`；首页闭包中不再有约 127KB 的 `template-config` 分包。首页包检查新增：客户端首页闭包
  含 zod schema 实现（`invalid_type`、`ZodError`）时，设置了 `homeScriptGzipBudget` 判失败，未设置只警告（首页在浏览器端用 zod
  校验表单的项目升级后不会因此构建失败）。模板配置必须是纯数据（含函数、Date 时构建失败，值为 `undefined` 的属性视同省略）。
- **`marketing.performance`**（`@product-res/config` 默认值保持此前行为，模板示例全部开启）：
  - `hydration: 'after-paint'`：预渲染页去掉 modulepreload，水合入口在首次内容绘制后由内联加载器插入（不支持 paint 观察时用 load 事件，最晚 3 秒）；
  - `criticalCss: 'used'`：每页只内联本页 DOM 用到的规则（构建期 beasties，另保留全部 `@font-face`、`.dark`、`:has()` 与类名都出现在本页的规则），
    完整样式表首帧后加载，另以 `<noscript>` 引入供关闭 JS 的访客使用；
  - `homeScriptGzipBudget`：首页客户端闭包 gzip 预算（字节），超出时构建失败；
  - 构建后处理逐页比对 head 的 title、meta、canonical、alternate、图标与 JSON-LD，不一致即构建失败。
- 新增开发依赖 `beasties`（`apps/web`，只在构建期使用）；新增验收脚本 `apps/web/scripts/check-critical-css.mjs`（关键样式与完整样式截图逐像素比对）。
- 只作用于 Cloudflare 构建（`pnpm build`）的预渲染 HTML；Worker 动态渲染的页面（定价页、登录后页面）与自托管构建不变。

## 配置变更

两项都是可选的，衍生项目按需启用：

1. **字体预加载**：营销页不用 Inter（`brand.css` 用 `--font-sans` 换成了别的字体）时，在 `apps/web/src/features/theme/fonts.project.ts` 改为：

   ```ts
   export function projectFontPreloads(): readonly FontPreload[] {
     return []
   }
   ```

   需要预加载自己的首屏字体时：`import brand from './brand-latin.woff2?url'`，返回 `[{ href: brand, type: 'font/woff2' }]`。
   只预加载首屏正文确实使用、且体积小的子集；按 `unicode-range` 拆分的 CJK 字体不要预加载。
2. **营销页关键路径**：在项目的 `template.config.ts` 的 `marketing` 中加入（模板同步合并时若已自动带入，核对数值）：

   ```ts
   performance: {
     hydration: 'after-paint',
     criticalCss: 'used',
     homeScriptGzipBudget: 220000, // 先 pnpm build 看「首页包检查通过：… gzip 合计 N B」，取 N 加约 5%
   },
   ```

   取舍：首帧与 LCP 更早；水合晚开始约一个首帧时间，首帧到水合完成之间点击按钮（主题切换、语言选择等）无响应，链接仍可正常跳转。
   项目自己在 head 中插入的、依赖水合时机的内联脚本需自行核对。

## 验证

```sh
pnpm --filter @<scope>/web exec vitest run --project unit scripts src/features/theme
pnpm --filter @<scope>/config test
pnpm --filter @<scope>/web build      # 日志：inline-critical-css … criticalCss=used，hydration=after-paint；首页包检查通过 … / 预算 …
```

启用 `criticalCss: 'used'` 后做一次视觉核对（需要先构建）：

```sh
cd apps/web && npx vite preview --port 4173 &
node scripts/check-critical-css.mjs http://localhost:4173 test-results/critical-css /,/zh,/blog   # 列出项目的主要营销页
```

输出「0 组不一致」即关键样式与完整样式在 390 / 1280 宽、浅色 / 深色下逐像素一致；不一致时目录中有两张对照截图。
常见原因是首屏元素的类名由客户端脚本在水合后才加上（预渲染 DOM 中没有），这类规则只会随完整样式表到达；把类名写进服务端输出即可。
项目有多站点（按 host 区分）时，对每个站点的 host 各跑一次。

Lighthouse 复测沿用项目原方法（移动端 simulate、三次取中位数）；首帧前完成的请求可在报告 `network-requests` 中与 `observedLargestContentfulPaint` 对照。

## 回滚

把 `marketing.performance` 改回默认（或删除该段）并重新构建即可恢复此前的 HTML；`fonts.project.ts` 返回 `defaults` 即恢复 Inter 预加载。

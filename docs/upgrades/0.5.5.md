## 概要

0.5.4 营销页关键路径的三项修正，来自衍生项目启用 `criticalCss: 'used'` 与 `homeScriptGzipBudget` 后的反馈。

- **关键样式保留规则**（`apps/web/scripts/marketing-html.mjs`）：beasties 裁剪时会整条丢弃两类规则，现默认保留：
  - 按根元素属性切换的规则：`:root[data-site=east]`、`:root[data-site]:lang(ko)`、`html[data-x=y] .a` 等。条件（`[a]`、`[a=v]`、`:lang()`）
    全部与本页 `<html>` 相符时保留（新增 `rootAttributes`、`RootAttributeRule`）；此前多站点 / 多语言项目的品牌 token 会从关键样式中消失。
  - `::before` / `::after` 以外的伪元素规则（`::placeholder`、`::file-selector-button`、`::-webkit-*` 等，并入 `DEFAULT_ALLOW_RULES`）；
    此前表单占位文字颜色等在首帧与完整样式不一致。
- **新增项目自有文件** `apps/web/scripts/critical-css.project.mjs`：`projectCriticalCssAllowRules(defaults)` 默认原样返回模板规则，
  项目可追加 beasties 判断不了的选择器（字符串或 RegExp），不必改模板文件。`optimizeHtml` 新增可选第四参数 `{ allowRules }`。
- **视觉核对脚本**（`check-critical-css.mjs`）：只拦截页面 `<noscript>` 回退中列出的延后样式表，项目在首帧后自行插入的样式表（如站点字体）
  两侧都加载；页面等到 network idle 再截图。此前它拦截全部 `/assets/*.css`，有站点字体样式表的项目会全部误判为不一致。
- **首页不再静态依赖 zod**：`apps/web/src/security-client.ts` 不再 `import { config } from 'zod'`，改为直接写 zod v4 的全局配置对象
  `globalThis.__zod_globalConfig`（`security-client.test.ts` 核对 zod 读到同一对象）。打包器会把 `config` 放进含整套 zod 的共享分包
  （约 35KB gzip），是否被拉进首页取决于分包结果——模板示例恰好没有，路由多的衍生项目首页闭包因此含 zod，设置预算即构建失败。
  模板示例首页 gzip 208220 B → 204660 B。
- `template-sync` 的项目自有清单补上 `fonts.project.ts`（0.5.4 漏登记）与 `critical-css.project.mjs`。

## 配置变更

无。已设置 `homeScriptGzipBudget` 的项目可按新的「首页包检查通过 … gzip 合计 N B」下调预算；0.5.4 因首页含 zod 未能设置预算的项目，
升级后重新构建，日志中不再有「客户端静态依赖中有 zod schema 实现」警告即可按 N 加约 5% 设置。

在 `marketing-html.mjs` 上自行加过 `RootAttributeRule` / 伪元素规则的项目：同步时采用模板版本，删除项目副本中的同名实现；
模板默认规则之外仍需要的保留规则移到 `apps/web/scripts/critical-css.project.mjs`：

```js
export function projectCriticalCssAllowRules(defaults) {
  return [...defaults, /\.js-only-banner\b/]
}
```

用变体脚本做视觉核对的项目可改回模板的 `check-critical-css.mjs`。

## 回滚

回退本版本代码即可；`critical-css.project.mjs` 不被模板文件以外的代码引用时可保留。

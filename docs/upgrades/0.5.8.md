## 概要

衍生项目同步 0.5.6 后反馈的跟进：首页包检查列出的 zod 来源更准确，路由 search 校验与 z.uuid() 规则一致并补 `optionalUuid`，
一个单测在完整测试负载下的超时放宽。

- **`check-home-bundle` 的 zod 来源**：改按 sourcemap 的 `names` 判断——只列出生成代码中实际使用了自身 zod 导入绑定（`z`、`z.object` 等）
  的项目源文件。server function 的 `.validator()` 在客户端被移除后只剩桩代码的 `*.functions.ts`、组件里用 zod 但已拆进懒加载分包的路由
  不再出现；`?tsr-shared=1` 虚拟模块并入原文件。sourcemap 没有 `names` 或按名称一个也没找到时，退回为列出有生成代码且导入 zod 的项目源文件。
  模板实测：把 `login.tsx` 的 `validateSearch` 临时改回 zod，旧规则列出 14 个文件，新规则只列出 `src/routes/(auth)/login.tsx`。
- **`features/routing/search.ts`**：
  - `requiredUuid` 改为与 zod v4 `z.uuid()` 相同的规则（版本位 1-8、变体位 `8/9/a/b`，另接受全 0 与全 f），此前接受任意 8-4-4-4-12 十六进制串；
  - 新增 `optionalUuid(value)`：不合法时视为未提供；
  - 注释写明 `optionalString` 把数字 / 布尔转回字符串后，TanStack Router 的规范 URL 会把 `?error=123` 写成 `?error=%22123%22`，
    访问原地址会被重定向到规范形式。
- **`fault-evidence.test.ts`**：超时放宽到 30 秒（每个用例重新导入 staging-acceptance 辅助模块，完整 `pnpm test` 并发负载下曾超过默认 5 秒，
  导致 template-sync 的验证误报失败）。

- **补充 0.5.6**：0.5.6 升级说明只列出了模板自带的路由。衍生项目自有路由（如 `register.tsx`、项目页面）若在 `validateSearch`
  中仍使用 zod，构建时首页包检查会按上述新规则列出这些文件，同样改用 `features/routing/search.ts`。

# 中国大陆商品网站：跨境采购补证的官方自动获取渠道（2026-09-21）

## 研究范围与结论

目标是为补证工作台判断：国内商品网站能否自动带回商品属性、阶梯价、MOQ、供应商身份，还是只能留下公开链接并由人发询价。本文只采用平台或平台条款的公开一手资料；没有创建账号、申请开发者权限、输入凭据或联系供应商。

首版建议做成“两层”接入：

1. **无凭据的链接识别 + 人工确认**：识别 1688/义乌购 URL，保存商品标题、商品链接、页面截图/快照、页面上可见的价格/MOQ/属性和供应商信息，并把每个字段标为“页面公开值、抓取时间、待供应商确认”。这可以先支持补证工作台，但不能宣称已接通官方 API，也不能把公开参考价当成正式报价。
2. **有资质后的官方合作接入**：优先评估 1688 开放平台；小商品类目另评估义乌购的官方合作/API 模式。两者都需要以平台当前开发者/合作伙伴审核结果为准，不能在没有 token、应用权限或合作确认时实现假接口。

核心判断：1688 的官方资料足以证明存在商品 API 和跨境采购场景，但公开首页没有给出本项目所需的具体商品字段、OAuth scope、AppKey/AppSecret 申请条件或 MOQ/阶梯价返回保证。义乌购官方页明确承诺“商品&商铺信息 API 对接”和条件筛选，但未公开 endpoint、字段清单、鉴权方式或价格/MOQ 保证。两者当前都应被建模为“候选官方渠道”，而不是已经连通的 API。

## 1. 1688 开放平台

### 官方事实

- 1688 官方开放平台首页列出“商品”API 能力，并把 API 能力描述为按模块提供的接口集合；同页还列出会员、旺铺、订单、支付、物流、服务市场等模块。来源：[阿里巴巴开放平台首页](https://aop.alibaba.com/)（页面标注 open.1688.com，API 开发能力段）。
- 官方首页明确描述“跨境电商”场景：面向跨境电商平台开店的 1688 采购商，支持智能选款、一键铺货、自动下单、批量支付和订单信息同步。来源同上，`跨境电商 / Cross-border Business` 段。
- 官方首页还描述铺货分销场景中的一键铺货、订单回流、批量支付、自动发货；这证明平台有面向 ISV/服务商的采购与分销对接方向，但不等于任意买家都能调用这些能力。来源同上，`铺货分销` 段。
- 1688 官方用户授权协议写明：用户在订购服务时授权服务商使用 1688 开放平台数据接口调用其 1688 账号及关联店铺/系统数据；接口范围取决于所订购服务和所需数据，平台按“最小原则”开放。来源：[1688 用户授权协议](https://terms.alicdn.com/legal-agreement/terms/suit_bu1_b2b/suit_bu1_b2b202112221916_15367.html)，第 1 条。
- 同一协议列举可授权的数据类别，包括商品信息、旺铺信息、营销信息；交易场景还包括脱敏订单、买家铺货及订单回流等。来源同上，第 1 条数据表。它说明商品数据确实属于授权数据范围，但没有承诺任意应用都能拿到全部字段。

### 对补证字段的可得性判断

| 字段 | 公开商品页/链接阶段 | 官方 API 阶段 | 判断依据与限制 |
|---|---|---|---|
| 商品标题、图片、公开属性 | 通常可由页面人工确认或合规的页面识别流程记录 | 商品 API 方向明确存在，但字段级返回未在公开首页确认 | 1688 官方只公开“商品”模块；不要凭第三方博客臆造接口或字段 |
| 阶梯价、MOQ/起订量 | 页面可能显示，必须保存页面原文/截图和抓取时间 | 公开官方首页未保证这些字段，也未公开本项目可用的权限范围 | 页面价格只能作为参考值；供应商确认后才可成为报价证据 |
| 供应商/旺铺身份 | 页面通常可见；先保存店铺 URL、店名、页面显示的公司/经营信息 | 官方授权范围包含“旺铺信息”，但是否包含完整主体资质、是否需店铺授权未公开确认 | 不应从商品页推断工厂、OEM 能力或真实产能 |
| 询价回复、定制价、交期 | 不会由商品公开页可靠给出 | 官方首页/授权协议没有承诺询价回复 API | 必须保留人工询价记录或供应商正式文件 |

### 认证、授权与权限：已知和未知

**已知事实**：官方协议要求在服务商场景由企业/个人用户作出授权；服务商要使用关联账号/店铺数据；开放数据遵循最小权限。官方首页提供“控制中心”“应用接入”“技术文档”“ISV 开发协议”“技术服务协议”等入口。[首页](https://aop.alibaba.com/)；[授权协议](https://terms.alicdn.com/legal-agreement/terms/suit_bu1_b2b/suit_bu1_b2b202112221916_15367.html)。

**尚未从可访问的一手公开页面确认**：具体 OAuth 授权码/令牌流程、AppKey/AppSecret 是否对本项目开放、开发者企业资质清单、商品读取 scope 名称、调用额度、沙箱条件，以及商品详情是否保证返回阶梯价/MOQ。官方开发文档在本次公开检索中动态入口未能稳定展开；因此本文不写 endpoint、scope 或字段名，也不引用第三方 API 聚合商的“官方接口”说法。

### 对首版产品的建议

- 允许用户粘贴 1688 商品链接；解析出平台、商品 URL、标题和可见字段后，全部标记为“公开参考值”。
- 把 `price_reference`、`moq_reference`、`attributes_reference`、`supplier_reference` 与 `quote_status` 分开；`quote_status` 初始为 `needs_supplier_confirmation`。
- 在真正申请 1688 应用权限前，先把“需要店铺/账号授权”的用户流程、撤销授权、字段最小化和凭据不落库设计清楚。当前代码不能显示“1688 API 已连接”。

## 2. 义乌购（Yiwugo）

### 官方事实

- 义乌购官方海外合作页把平台定位为服务义乌小商品全球贸易，并称平台提供商品和商家信息。来源：[Looking For Partners of Yiwugo Overseas Cooperation](https://en.yiwugo.com/partners/index.html)，第 4–12 行（页面内容）。
- 模式一“义乌购海外官方授权合作伙伴”明确列出“中英文站商品&商铺信息 API 对接”，并列出按区域获得官方授权、获得相关区域询盘信息支持、协助组货发货等支持。来源同上，`模式一` 段。
- 模式二“API 接口商品信息对接”明确列出“中英文站商品&商铺信息 API 对接”，并称合作伙伴可按条件筛选产品、选择隐藏或展示义乌购相关信息、获得组货发货协助。来源同上，`模式二` 段。
- 模式三是本地外贸合作伙伴：义乌购提供真实采购需求信息，由合作伙伴处理采购需求并实现交易。来源同上，`模式三` 段。它是询盘/合作渠道，不应被误标成商品详情 API。
- 官方商品页面的公开搜索结果可显示价格和起购量示例，例如某商品显示 `¥21.00`、`10个 起购`、`¥19.00`、`≥100个`，还显示发货地、运费规则、重量和服务承诺。来源：[义乌购商品页示例](https://wap.yiwugo.com/products/979353174)。这证明页面层面可能有阶梯价/MOQ，但不能推导所有商品都具备同样结构，也不能替代供应商确认。

### 对补证字段的可得性判断

| 字段 | 无凭据链接阶段 | 官方合作/API阶段 | 判断依据与限制 |
|---|---|---|---|
| 商品属性、标题、图片 | 商品页面可人工确认并存档 | 官方页承诺商品信息 API | 官方未公开字段字典和版本，需合作接入后实测 |
| 阶梯价、MOQ/起购量 | 某些公开页面可见；示例中同时出现单价和起购量 | 官方页只承诺商品信息 API，未承诺阶梯价/MOQ 字段 | 应保存原始页面证据，并标“参考价/页面起购量” |
| 商铺/供应商信息 | 页面可保存商铺 URL、店名及显示信息 | 官方页明确承诺商铺信息 API | 不应把平台展示商铺直接等同于已核验制造商或 OEM 工厂 |
| 询价回复/采购需求 | 需要人工发起和记录 | 模式一/三提到区域询盘或真实采购需求支持，但非公开详情字段接口 | 应独立建模为 inquiry 状态与人工证据 |

### 认证、授权与权限：已知和未知

**已知事实**：义乌购把 API 对接放在“海外官方授权合作伙伴”或“API 接口商品信息对接”合作模式中；页面公开了海外合作邮箱 `overseas@yiwugo.com`，但没有给出自助开发者注册、AppKey、OAuth、token、endpoint、费率或调用额度。[官方合作页](https://en.yiwugo.com/partners/index.html)。

**尚未确认**：是否必须企业资质、区域独家是否为必要条件、API 是否开放给非海外授权伙伴、商品价格/MOQ 是否在 API 返回、供应商主体资质字段是否可取。不能因为页面给出合作邮箱，就在产品中伪造“已申请/已接通”。

### 对首版产品的建议

- 先支持识别 `yiwugo.com` / `wap.yiwugo.com` 链接，记录页面公开的商品、商铺、价格、起购量、发货地和时间戳。
- 把“商品信息 API”与“询盘/采购需求”分成两个连接器状态；后者只能在收到合作方/供应商回复后进入 `supplier_confirmed`。
- 如果业务确实集中在义乌小商品，再由项目负责人用企业身份走官方合作咨询；在得到字段和授权书面确认前，不承诺阶梯价、MOQ 或公司资质自动同步。

## 3. 为什么首版不把公开参考价当正式报价

商品页中的数字是平台展示值，可能受 SKU、采购数量、地区运费、活动、库存、定制要求、税费和有效期影响。1688 官方授权协议也把商品信息与交易/服务授权区分开来；义乌购示例同时展示起购量、阶梯价、地区运费和服务承诺。故工作台应把“页面公开参考价”与“供应商正式报价”分成不同证据等级：

- **页面参考**：URL、抓取时间、截图/快照、页面原文、货币/单位、SKU/数量条件。
- **供应商确认**：供应商身份、报价有效期、数量阶梯、MOQ、样品费、定制费、交期、贸易条款、运费/税费，以及对方可核验的书面回复。

## 4. 落地优先级

1. **P0：无凭据工作台**——URL 识别、页面字段人工录入/复核、证据快照、参考价与正式报价分级；支持线下厂商完全手工录入。
2. **P1：1688 官方接入评估**——使用企业身份进入官方控制中心/应用接入，确认商品 API 的实际字段、授权范围、回调和调用限制；确认后再实现正式连接器。
3. **P2：义乌购合作/API 评估**——通过官方合作页公开渠道询问合作模式、资质、字段、鉴权和价格/MOQ 数据可用性；未获确认前继续使用链接识别和人工录入。

## 5. 资料限制与证据边界

本次检索可稳定读取 1688 官方首页、1688 官方授权协议、义乌购官方海外合作页；1688 的“开发指南/技术文档/应用接入”属于动态入口，本次未能从公开页面稳定获得具体 endpoint、OAuth scope、AppKey/AppSecret 规则，因此有意不编造这些细节。义乌购合作页同样只公开合作模式和能力概述，没有公开 API 规范。所有“可自动取得哪些字段”的结论都按上述公开证据分为“页面可见”“官方方向明确”“尚待授权/实测”，不把推断写成已接通事实。

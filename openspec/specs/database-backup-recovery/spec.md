# database-backup-recovery Specification

## Purpose
定义单机自托管数据库的备份与恢复保证，通过连续归档、分层保留、独立副本和真实指定时间点恢复演练，确保业务与后台任务的持久状态可以在新环境中被核验和恢复。

## Requirements

### Requirement: 每日基础备份与连续归档
自托管 SHALL 每日执行 PG 全集群基础备份并持续归档 WAL 到可配置 endpoint/region/bucket/prefix/path-style 的 S3 兼容目标，不依赖云主机元数据。备份 SHALL 覆盖业务、角色、任务引擎、队列/事件/调度状态；失败 MUST 可查询且归档失败 MUST 不伪报成功。（B1）

#### Scenario: 正常备份周期
- **WHEN** PG 持续写入且每日备份到期
- **THEN** S3 包含完整 base 与连续 WAL/timeline 链，状态显示成功时间与可恢复上界，不输出凭据或业务正文

#### Scenario: 归档目标不可达
- **WHEN** 上传失败
- **THEN** 归档返回失败并可观察延迟/磁盘风险，不删除尚未成功归档的 WAL，也不将备份周期记为成功

### Requirement: 可配置的安全分层保留
保留策略 SHALL 默认保留最近 7 天的每日备份及最近 4 周的每周锚点，可配置。清理 MUST 保留全部仍承诺恢复时间点所需 base、WAL 和 timeline history；新备份或完整性验证失败 MUST 不删除上一份可用备份。（B1）

#### Scenario: 超过每日窗口的每周锚点
- **WHEN** 清理运行且某 weekly base 超过七天但仍在四周保留期
- **THEN** 该 base 与恢复所需 WAL 链仍可用，指定时间点恢复通过

#### Scenario: 清理失败周期
- **WHEN** 新 base 未成功、归档链缺失或目标同步失败
- **THEN** 返回明确失败并保留可用恢复链，不执行破坏性过期删除

### Requirement: 每日逻辑备份
自托管 SHALL 每日生成可恢复的 pg_dump 逻辑备份，包含业务及任务 schema，并提供角色/权限恢复材料。逻辑备份失败 MUST 非零退出并可查询；逻辑备份 MUST 不被宣称为连续 PITR。（B2）

#### Scenario: 逻辑恢复校验
- **WHEN** 将完成的每日 dump 恢复到隔离 PG
- **THEN** 表、约束、业务和任务数据可读取，恢复权限可核验，备份日志不含连接串或正文

### Requirement: 新环境指定时间点恢复
交付 SHALL 提供脚本/runbook 将 S3 base 与 WAL 恢复到新服务器的显式 UTC 时间点。恢复 MUST 使用新空卷、覆盖全集群持久状态且默认不启动业务副作用；WAL 缺失、目标越界或目录不安全 MUST 失败，不静默恢复为最新。（B3）

#### Scenario: 成功 PITR
- **WHEN** 选择合法目标时间、匹配 PG/应用版本及完整备份链
- **THEN** 恢复到指定时间点并报告实际恢复位置，校验后才能显式 promote/接流量，密钥/TLS 和外部对象边界有恢复说明

#### Scenario: 非空卷或恢复链不足
- **WHEN** 指向生产/非空卷，或无法取得目标所需 WAL
- **THEN** 非零退出、不覆盖已有数据、不启动 jobs、不以较新或较旧数据冒充目标恢复

### Requirement: 隔离恢复演练证明
交付 SHALL 提供脚本从 S3 恢复到本地或服务器临时实例并校验。演练 SHALL 证明目标时间前数据存在、之后数据不存在，校验业务不变量、角色和任务状态，记录耗时/恢复点。演练 MUST 无公网数据端口、无生产副作用，仅清理自己创建的资源。（B4、§6.7）

#### Scenario: 真实指定点演练
- **WHEN** 生成目标时间前后 marker、完成真实 S3 备份/归档并运行演练
- **THEN** 恢复实例通过 marker 和 schema/任务校验，启用积分时通过余额对账，输出脱敏结果与恢复耗时

#### Scenario: 演练失败
- **WHEN** 校验不符或恢复失败
- **THEN** 非零退出并保留必要诊断，生产卷和服务不受影响，不将演练标记成功

### Requirement: 独立凭据恢复副本
自托管 SHALL 支持将 base、逻辑备份、WAL 与 timeline history 同步到独立凭据的目标，允许使用不同供应商/账号，校验复制并报告连续恢复上界与延迟。本次服务器验收按 2026-10-16 用户决定使用同一 R2 账号下独立桶及仅限对应桶的独立 token，SHALL 记录失去供应商独立性及账号级共同故障风险，不宣称跨供应商或独立账号容灾。同步 MUST 不传播源端删除；副本 SHALL 独立保留，单方失败 MUST 可见。（B5）

#### Scenario: 主目标凭据不可用
- **WHEN** 演练只提供副本桶受限 token、不挂载主凭据，且验证副本 token 无主桶权限
- **THEN** 可从第二目标独立恢复到其已确认上界内的指定时间点并通过相同校验

#### Scenario: 副本同步失败或源端删除
- **WHEN** 第二目标不可达或源目标已有删除
- **THEN** 明确报告副本未完成及其恢复上界，已存在副本不因源删除被清空，主 PG 归档不等待副本才能完成

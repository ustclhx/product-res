# Spec Delta

## Purpose

用 Keepa 历史回放和权重拟合改进算法，并在页面中展示验证结果。

## ADDED Requirements

### Requirement: Keepa 历史回放
团队 SHALL 能对 Amazon 方向选择历史节点发起回放：用节点前的 Keepa 历史计算当时的分数并冻结为回放样本，再用节点后的数据打标签。回放 MUST 遵守 Keepa 额度，回放样本 SHALL 单独标注。

#### Scenario: 额度不足顺延
- **WHEN** 回放需要的 Keepa token 超过当前余量
- **THEN** 回放任务顺延到额度恢复，不超额调用

### Requirement: 权重拟合建议
有效样本达到下限后，系统 SHALL 用逻辑回归拟合维度权重并给出建议、交叉验证指标与和当前权重的对比；只有团队确认采用后才生成新的评分设置版本。

#### Scenario: 忽略建议
- **WHEN** 团队忽略一条权重建议
- **THEN** 评分设置不变，建议标记为已忽略

### Requirement: 算法验证页面
算法验证页面 SHALL 显示准备度矩阵、按月命中率曲线、样本构成（影子 / 回放 / 导入）、待打标签数和权重建议；数据中心的评分维度管理 SHALL 在每个维度旁显示回测命中率。

#### Scenario: 冷启动说明
- **WHEN** 所有组合都处于冷启动
- **THEN** 页面说明需要积累的样本数与预计时间，不显示命中率曲线的示例数据

# Design

## 决策

### D1 表（空间级）

| 表 | 说明 |
|---|---|
| `recommendation` | 线索 × 冻结日期：平台、方向、信号类型（主导维度）、综合分、等级、置信度、权重版本、输入引用快照、样本类型（shadow / replay / import） |
| `recommendation_label` | 推荐 × 窗口（14 / 30 / 60）：是否命中、实际销量增量、价格跌幅、高峰周误差、所用来源、打标时间；数据不足时为 `insufficient` |
| `readiness_stat` | 平台 × 方向 × 信号类型 × 计算日：样本数（分类型）、命中数、Wilson 下界、基线、等级 |
| `weight_suggestion` | 拟合时间、样本数、建议权重、当前权重、交叉验证指标、状态（proposed / accepted / dismissed） |

### D2 打标签

- 到期条件：冻结日 + 窗口天数 ≤ 今天，且该窗口未打标签。
- 命中（默认 X=30、Y=15、窗口 30）：簇在窗口内的销量增量 ≥ X，且竞品中位价跌幅 ≤ Y%。季节类（主导维度为增长与季节）另要求高峰周预测误差 ≤ 2 周。
- 窗口内关键观测缺失超过一半 → `insufficient`，不计入命中率分母。

### D3 准备度

- Wilson 下界（z = 1.96）。基线 = 同方向随机抽取新品的命中率（每周按同样标准对随机样本打标签）。
- 等级：样本 < 20 冷启动；20–50 观察期（置信度上限“中”）；≥ 50 且下界 ≥ 基线为可用；≥ 100、权重已校准且最近 3 个月命中率稳定（月度命中率标准差 ≤ 0.1）为可信。阈值可配置。
- 样本加权：影子推荐 1.0，Keepa 回放 0.5，导入 0.3（可配置），用于等级判断的有效样本数 = 加权和。

### D4 Keepa 回放

团队选择 Amazon 方向与历史节点，任务用 Keepa 历史（价格、BSR、卖家数、销量估算序列）截取到节点前 T 日，调用 `packages/selection` 的同一套信号函数计算分数，冻结为 replay 推荐，再用节点后的序列打标签。Keepa 调用遵守额度账本（预估 token，超出顺延）。

### D5 权重拟合

有效样本 ≥ 50 时允许拟合：特征 = 7 维分数（缺失用该维度样本均值并加缺失指示），标签 = T+30 命中；L2 逻辑回归，5 折交叉验证报告 AUC 与命中率提升；权重归一到与现有设置同尺度。建议需团队点“采用”才生成新评分设置版本。

### D6 页面

`/app/$slug/validation`：准备度矩阵（平台 × 方向 × 信号类型）、命中率曲线（按月）、样本构成、到期待打标签数、权重建议卡片（对比表 + 采用/忽略）、回放任务入口与状态。

## 风险与取舍

- 前几个月 eBay 样本很少，准备度长期为冷启动属正常；界面明确说明。
- 逻辑回归在小样本下不稳定，所以设下限并要求人工确认。

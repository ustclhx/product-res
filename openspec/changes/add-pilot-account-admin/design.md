## Context

现有会话绑定一个工作区，服务端角色为 analyst、decision、contributor。控制库 v1 持有用户、成员和会话，业务库独立。管理员沿用同一登录和 CSRF/Origin 机制。

## Goals / Non-Goals

Goals：管理员可独立维护试点成员；所有操作可追溯、并发修改可检测，旧账号和业务数据保持可用。

Non-Goals：公开注册、邮件邀请、SSO、多级管理员、管理员自动取得采购审批权、删除业务用户历史。

## Decisions

- `is_admin` 为服务端全局账号管理标识，独立于工作区业务角色；admin 初始以 contributor 加入现有两个工作区，满足现有登录要求，不改审批规则。
- 管理端列表、创建、编辑、随机重置密码位于 `/admin/accounts`；工作区角色从服务端已存在工作区中选择，不接收路径或任意权限字符串。
- 控制库 v2 原子迁移，用户带版本号。编辑及密码重置要求 expected_version；权限变动、禁用和重置密码撤销相关会话。
- 创建和重置采用密码学随机口令，数据库只存 scrypt 哈希，响应只返回一次明文，不在日志、审计、浏览器存储或普通查询中保留。网络结果不确定时先刷新查账号状态，不能自动重复创建。
- 管理审计与账号修改在同一事务，保护自我禁用和自我成员变动，管理接口不开放管理员授予。
- 界面为现有样式的账号表格及创建/编辑表单，角色中文展示；普通成员不显示入口且直接调用 API 仍被拒绝。

## Risks / Trade-offs

- 管理员重置密码会使原会话退出 → 操作明确标注，并二次点击确认。
- 控制库升级后旧镜像无法读取 → 发布前停写备份；回滚必须同时恢复相容控制库，不能仅切旧镜像。
- 管理员拥有跨工作区账号配置能力 → 服务端逐请求鉴权，普通成员不能越权；管理权限不自动绕过业务负责人校验。

## Migration Plan

先跑迁移/权限/会话回归及浏览器账号流程，在本机构建两个镜像。ECS 只停止 product-res 组件并备份一致性数据；升级 API/worker 与 gateway，创建 admin，验证登录、管理 API、旧账号以及原有业务记录。随机密码保存在忽略目录的私有交付文件中。发布失败先保留故障数据，再恢复备份及旧镜像。

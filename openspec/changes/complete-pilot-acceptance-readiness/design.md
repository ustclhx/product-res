## Context
参见 proposal.md 和 docs/pilot/next-steps-2026-09-22.md。延续通用不可变 entity、execute 幂等/版本与工作区隔离。保持已归档 D4/D5 和原批准经营闭环。

## Goals / Non-Goals
工程交付到可验收，包括部署与受控回归。真实业务决策、询盘发送、采购、授权国内平台和域名配置不由开发代替。

## Decisions
1. 研究结论使用独立 research_conclusion 实体（STOP/HOLD），由项目决策人提交，引用同候选证据、冻结标准及来源，明确数据来源 REAL/TEST/DEMO，必须有原因和下一轮启示。不创建批准/经营 outcome，不自动改变正式候选状态；研究处置单独显示。反馈复用 feedback+criteria 修订及现有下一项目采用机制，research_conclusion_id 与 outcome_id 互斥。
2. 反馈可从空 rules 提出新规则，也可保持规则仅改变 required_evidence 或记录可继承的 research_learning；空建议仍拒绝。确认由决策人执行，保留旧快照和来源链。研究闭环单独统计，不把 HOLD 当商业成功或结束候选。原 9.3 经营验收保持未变。
3. source 可追溯性统一检查当前候选自身来源（批次或人工链接/来源说明），对标引用单列，不伪造自身价格。研究进度由结论、已确认反馈、下一项目构成，经营进度继续使用批准链。
4. D2 增量兼容报价字段：价格阶梯按明确数量范围保存；样品、现货、定制 MOQ 分开，保留原 amount/moq 主口径；不自动选最低价供筛选。共享原件仅 http(s) 链接+材料说明，不主动抓取。实车通过要求左右前排结构化检查、样品和目标车辆一致；旧记录只展示不追溯篡改。
5. D6 历史批次复用不消耗新请求，显式刷新创建新 job，所有额度仍服务端检查；未知结果不自动重发，提供核对恢复或明确新请求动作。复用当前受控 reconcile，不接收任意外部内容。重复商品纳入追加观察不覆盖核验证据。
6. UI 延续 DESIGN.md，一次主动作，采购细节折叠，研究与经营标签明确。运维脚本仅管理本项目本机隧道，不共享 root 给团队，文档包含各成员授权路径。

## Risks / Trade-offs
研究回流误读为经营验证 → 单独计数和说明；历史报价兼容 → 新字段可选但新实车 PASS 强校验；重复请求费用 → 显式刷新、额度可见、未知不重试；共享链接失效 → 保留说明并由团队核验访问权限。

## Migration Plan
增量 JSON entity 无 schema 破坏。先完整离线测试、浏览器回归；ECS 停写备份、独立镜像发布、健康和只读 smoke，保留旧镜像及恢复说明。不修改共享 NewAPI 配置或伪造真实业务记录。

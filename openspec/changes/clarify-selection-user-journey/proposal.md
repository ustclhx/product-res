## Why

现有入口围绕功能堆叠，创建项目后没有续接下一步，候选入口位于配置之后，工作台混合每日工作和试点验收。需要按已确认的使用链条完成一次整体调整，让业务成员知道当前工作、责任人和下一步。

## What Changes

- 两步建立项目，保存后进入项目；确认标准后直接添加候选。
- 项目以候选与下一步为中心，标准、职责、历史为次级入口。
- 候选默认进入当前工作，提供可直接打开采购、适配、核验和决策的链接，研究暂缓/停止为决策分支。
- 统一只读事项投影，工作台展示我的工作、等待他人及项目；全部事项共享相同身份、状态和链接，逾期不重复计数。
- 将试点验收、工时和运行观察移到次级页面，保留能力与历史链接。
- 补齐角色、空状态、深链和端到端回归，并部署到现有 ECS 试点入口。

## Capabilities

### New Capabilities
- `guided-selection-journey`: 项目创建、候选操作和跨页面事项的一致用户链路。

### Modified Capabilities

无；本变更新增编排层，已有证据、审批、结果及权限业务规则继续有效。

## Impact

React 项目、候选、工作台、任务、路由与导航；FastAPI 新增只读工作事项 API；相应行为测试与交付文档。复用现有 SQLite 实体和命令接口，无新增外部调用、依赖或数据库迁移。

# Design

## 背景

方案见 `docs/plan/selection-workbench.md` 第 4、8、9 节。金额按最小单位整数（美分）存储，币种显式；汇率取 `fx_rate` 观测的主值（fx-ecb 或手工）。

## 决策

### D1 表（空间级）

| 表 | 说明 |
|---|---|
| `supplier` | 名称、链接、平台（1688 / Alibaba / 其他）、备注 |
| `supplier_quote` | 供应商 × 商品簇：阶梯 `[{minQty, unitPriceMinor}]`、币种、MOQ、重量 g、尺寸 cm、可信度（public / confirmed）、报价日期、来源（manual / import） |
| `logistics_profile` | 名称、平台、类型（ebay-direct / ebay-overseas / amazon-fba / amazon-fbm）、时效天数、计费公式（JSON）、禁运属性 |
| `cost_param` | 平台 × 类目（可空 = 默认）：佣金率、固定费、广告率、退货预留率、仓储费、入库配置费 |
| `costing_scenario` | 线索 × 供应商报价 × 物流方案 × 跟卖方式：计算结果快照（各成本项、保本价、毛利率、最晚决定日、输入来源）、是否选定 |
| `decision` | 线索：跟卖 / 放弃、首批数量、目标售价、计划上架日、放弃原因、决定时的线索快照（分数、权重版本、所选组合、观测引用） |
| `follow_outcome` | 决定 × 回看：实际销量、实际售价、录入时间、与预测对比 |

### D2 核算公式（`packages/costing`）

```
采购 = 阶梯单价(计划数量) × (1 + 微改良改款费分摊)
头程 = 物流公式(重量, 体积重, 数量) ÷ 数量
平台费 = 售价 × 佣金率 + 固定费
配送/尾程 = FBA 配送费（SP-API 预估优先）或 直发运费 / 海外仓尾程
仓储 = 月仓储费 × 预计库存月数（Amazon）或 海外仓仓租
广告 = 售价 × 广告率；退货预留 = 售价 × 退货率
落地成本 = 采购 + 头程 + 配送/尾程 + 仓储 + 改款费分摊
净利润 = 售价 − 落地成本 − 平台费 − 广告 − 退货预留
保本价 = 解 净利润 = 0 的售价（费率项随售价线性变化）
```

- 售价默认取竞品中位价（簇内主值价格的中位数），可在矩阵中改。
- 任一必需输入缺失时该格显示“缺少：…”，不计算，不补默认 0。
- 最晚决定日沿用 `packages/selection` 的 deadline，物流时长来自方案，采购时长来自报价或默认值。

### D3 成本确定性

已确认报价 1.0、公开价 0.6；物流模板字段齐全 1.0、缺尺寸 0.5；FBA 费来自 SP-API 1.0、费率表 0.7；三项平均进入 M2 置信度。

### D4 状态流转

线索 `new → costing → pending → followed | dropped`。至少一个选定组合后进入 pending（待决定队列）。决定后写 `decision` 与 `lead_event`，线索不可再改核算（可新建复制）。

### D5 回看提醒

`selection-review-v1`（每日 09:00 SGT）：决定为跟卖且计划上架日 + 30 天已到、尚未录入回看的，发站内通知（复用 notifications）。

### D6 页面

- 线索详情增加“核算”标签：报价列表与录入、矩阵（供应商 × 物流 × 方式，高亮最优）、所选组合的成本瀑布（ECharts）。
- 工作台首页：KPI + 待决定队列（橙/红标记）+ 节点倒计时 + 数据同步与额度状态。
- `/app/$slug/archive`：已决定线索、筛选、30 天回看录入与对比。
- 设置页增加“物流方案 / 成本参数”标签。

## 风险与取舍

- 物流计费公式差异大，先支持首重续重、体积重、按方三种，复杂报价表通过导入后人工核对。
- FBA 配送费 SP-API 未接通前只能用费率表，成本确定性降低。

# Proposal

## Why

M1 已经把多个数据源的观测值统一到 `observation` 长表，但还没有任何东西把这些数据变成“该不该跟卖”的判断。M2 的目标是：团队配置选品方向与对标店铺池后，系统每天把同款商品归并成商品簇，按方案第 5 节的 7 个维度打分，过硬门槛，给出等级、置信度与风险提示，并在“跟卖选品”页面列出候选和详情。每条线索都必须能说明推荐理由和每个输入值的来源。

## What Changes

- 选品方向：名称、平台与站点（可多选）、类目、关键词、对标店铺池（种子 + 系统推荐后人工勾选）、关联节点、启用/停用。
- 节点日历：预置美国常见节点（返校季、万圣节、黑五/网一、圣诞、情人节、母亲节、父亲节、独立日、Prime Day），可增删改。
- 商品簇归并：GTIN/UPC/ePID/ASIN 精确关联 → 标题相似；记录每个成员的归并置信度，支持手动拆分与合并，修正记录保留。
- 信号与打分（`packages/selection`，纯函数）：市场需求、增长与季节、同行扩散、利润空间、竞争强度（反向）、供应与时效（反向）、合规与侵权（一票否决）。缺失输入的维度为空，不按 0 计；综合分只在已计算维度上按权重归一。
- 硬门槛、等级（推荐 ≥ 75 / 谨慎 50–74 / 不推荐 < 50）与置信度（第 11.1 节中 M2 可计算的项）；准备度为冷启动时只显示“未验证”。
- 风险检查（`packages/risk`，纯函数）：品牌库、VeRO 名单、受限类目、Amazon 品牌备案 ASIN、外观专利提示、禁运属性；高风险一票否决。
- 评分设置：维度权重、反向维度、一票否决阈值、硬门槛、毛利底线；修改生成新的权重版本。
- 每日流水线新增步骤：归并 → 信号 → 硬门槛 → 打分 → 置信度 → 线索。
- 页面：跟卖候选列表（平台切换、方向筛选、命中信号、置信度、风险标签、最晚决定日；eBay 不显示 BSR）、商品簇详情（7 维雷达、置信度、价格与销量曲线、季节曲线、风险明细、来源对比、拆分/合并）、选品方向与店铺池、设置中的节点日历与品牌库/风险规则、数据中心的评分维度管理。

## Capabilities

### New Capabilities

- `selection-directions`：选品方向、站点与类目范围、关键词、对标店铺池、节点日历。
- `product-clustering`：商品簇归并、归并置信度、手动拆分与合并。
- `selection-scoring`：7 维信号、硬门槛、综合分、等级、置信度、评分设置与权重版本。
- `risk-checks`：品牌库与风险规则、风险发现与一票否决。
- `follow-candidates`：候选列表、商品簇详情、方向与设置页面。

### Modified Capabilities

无。依赖 `market-data-model`（读取观测值与主值）、`data-sync`（每日流水线）。

## Impact

- 新增 `packages/selection`、`packages/risk`（纯函数，依赖 shared 与 datasources 的指标类型）。
- 新增空间级表（`scoped()`）：方向、方向范围、方向店铺、节点、品牌库、风险规则、评分设置、商品簇、簇成员、簇信号、线索、线索事件、风险发现。
- `apps/jobs` 每日流水线增加选品步骤；`apps/web` 增加跟卖选品与设置页面。
- 利润空间与供应时效维度在 M3 核算完成前只能用成本参数做粗估或为空；M3 接入后自动使用核算结果。

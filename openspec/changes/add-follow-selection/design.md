# Design

## 背景

方案见 `docs/plan/selection-workbench.md` 第 4、5、7、11、12 节。市场数据（商品、卖家、关键词、观测值）是部署级共享表；选品方向、商品簇与线索属于空间，用 `scoped()` 访问。团队共用一个账号，不做指派与审批。

## 决策

### D1 包与依赖

- `packages/selection`：纯函数。输入是“已读取好的观测序列 + 配置”，输出维度分、硬门槛结果、综合分、等级、置信度与解释。不访问数据库。
- `packages/risk`：纯函数。输入商品属性与规则，输出风险发现（类型、等级、依据、是否一票否决）。
- 读取与写库放在 `packages/marketdata`（市场数据读取）和新的 `apps/web/src/features/follow` / `apps/jobs/src/selection`（组合与持久化）。selection 和 risk 不依赖 db。

### D2 表（空间级，均带 `workspace_id`）

| 表 | 说明 |
|---|---|
| `direction` | 名称、平台/站点列表、类目 ID 列表、关键词、关联节点 ID、启用 |
| `direction_seller` | 方向 × 平台卖家（seed / suggested / accepted / rejected） |
| `seasonal_node` | 名称、每年月日、销售期天数、关联关键词；预置美国节点 |
| `brand_entry` | 品牌名、类型（brand / vero / registered）、平台、备注 |
| `risk_rule` | 类型（restricted-category / hazmat / certification / shipping-ban）、匹配条件（JSON）、等级、说明 |
| `scoring_setting` | 版本号、权重、反向维度、否决阈值、硬门槛、毛利底线、生效时间；只追加 |
| `cluster` | 方向、平台、代表商品、名称、状态 |
| `cluster_member` | 簇 × 平台商品、归并方式（gtin / platform-id / title）、置信度、手动锁定 |
| `cluster_signal` | 簇 × 日期 × 维度 → 分数（可空）、输入值与来源引用（JSON） |
| `lead` | 簇 × 日期：综合分、等级、置信度、门槛结果、权重版本、状态（new / costing / pending / followed / dropped） |
| `lead_event` | 线索事件流（状态变化、手动修正、备注） |
| `risk_finding` | 簇 × 风险类型 → 等级、依据、是否否决 |

### D3 归并

1. 同平台：平台 ID 相同即同一商品；GTIN/UPC/ePID 相同 → 同簇（置信度 0.95）。
2. 标题相似：小写、去品牌词与停用词、去数量单位后取词集合，Jaccard ≥ 0.6 且类目相同 → 同簇（置信度 = Jaccard）。
3. 标题向量与图片相似需要 AI/向量依赖，本期不做；接口预留 `similarity` 策略，后续加入。
4. 手动拆分/合并写 `lead_event` 与 `cluster_member.locked`，之后自动归并不覆盖锁定成员。

### D4 维度计算（0–100，缺失为 null）

| 维度 | M2 计算 |
|---|---|
| 市场需求 | eBay：簇内 `sold_quantity_total` 快照差分得 7 天增量，与 30 天日均比较得加速度；Amazon：`sales_estimate_monthly` 主值 + BSR 分位。分数用对数映射 + 加速度加成 |
| 增长与季节 | 关联节点的 `search_trend_index` 月度序列：季节指数（目标窗口均值 ÷ 全年均值）× 年际相关；叠加 90 天增长 |
| 同行扩散 | 14 天内首次出现同簇商品的对标店铺数，及上新时间集中度 |
| 利润空间 | 竞品中位价 − 成本参数估算（佣金、固定费、预设头程与退货率）；无落地成本输入时为 null（M3 核算后使用核算结果） |
| 竞争强度（反向） | 卖家数增长、最低价 30 天跌幅、头部份额、评论数中位数门槛 |
| 供应与时效（反向） | 最晚决定日余量；无核算时只用默认提前期，置信度降低 |
| 合规与侵权 | 100 − 风险扣分；高风险直接 0 并否决 |

映射函数与常数集中在 `packages/selection/src/scales.ts`，单元测试覆盖边界。

### D5 综合分、门槛与等级

- 综合分 = Σ(权重 × 分数') ÷ Σ(已计算维度的权重)，反向维度分数' = 100 − 分数。可计算维度少于 4 个时不给综合分。
- 硬门槛：合规分 < 否决阈值（默认 30）；所有物流方案都来不及（M3 前用默认提前期判断）；毛利率 < 底线（默认 15%，无利润数据时不判）。
- 等级按方案第 5.2 节；准备度为冷启动（M5 前全部视为冷启动）时等级显示“未验证”，仍保存计算出的等级。

### D6 置信度（M2 可计算项）

数据覆盖、数据新鲜度、信号一致性、来源一致性、归并可信度、季节规律稳定性、时间余量、竞争稳定性；成本确定性在 M3 加入，历史命中率在 M5 加入。总置信度为各项平均（0–1），显示为高 / 中 / 低。排序键 = 综合分 × 置信度；高分低置信标“值得关注但证据不足”。

### D7 流水线

在 `datasources-daily-v1` 之后新增 `selection-daily-v1`（04:00 SGT，missedRun once）：每个启用方向依次归并、计算信号、风险、打分、生成线索。同一方向同一天重复运行幂等（按 簇 × 日期 upsert）。

### D8 页面

- `/app/$slug/follow`：候选列表（DataTable）。列：商品簇、平台、等级、综合分、置信度、命中信号、风险标签、最晚决定日、来源徽标。
- `/app/$slug/follow/$clusterId`：雷达、置信度明细、曲线（ECharts）、风险卡片、来源对比、成员列表（拆分/合并）。
- `/app/$slug/follow/directions`：方向与店铺池。
- `/app/$slug/config`：节点日历、品牌库与风险规则（标签页）。
- 数据中心增加“评分维度管理”标签：权重、阈值，旁边预留回测命中率（M5 填充）。

## 风险与取舍

- 没有真实数据时所有维度为 null；用模拟连接器与夹具验证流水线。
- 标题 Jaccard 对同款不同描述的商品召回有限，后续加入向量相似。
- 权重等权起步，M5 拟合后由团队确认启用。

## Context

动机与范围见 proposal.md；原型基线见 `openspec/specs/`。用户已确定同机 ECS + NewAPI，一个合作团队和内部自建站团队，验收数据闭环而不设工时提升门槛。主机只有 2 核/约 3.5 GiB，现有服务占用 80/443/8080/3000；核查记录为 `docs/pilot/ecs-readiness-2026-09-20.md`。

现有业务持久化、幂等与快照可以保留，但 actor 由前端声明、时钟固定、发现纳入绑定 fixture，模拟模型在写事务内执行。这些都不能直接用于真实调用。字段解释、来源比较和初始口径见 `docs/pilot/data-fields-and-sources.md`。

## Goals / Non-Goals

Goals：一条可恢复、可核验的真实采集→证据→AI草稿→人工决定→验证→结果→新标准链路；两个团队数据隔离；离线测试保留；变更范围内的能力可部署并有回滚证据。

Non-Goals：通用 Agent 编排器、完整 SaaS 租户管理界面、自动建站/交易/投放、后台无限采集、模型训练、全渠道市场覆盖。店铺建站系统尚未确定，经营回流本轮使用与现有合同一致的手工/CSV，不假装已有自动经营连接器。

## Decisions

### 1. 两种运行模式与工作区隔离

`demo` 保留固定时钟、样例角色和重置；`pilot` 使用真实 UTC、服务端身份和来源标记。demo 与 pilot 使用不同进程配置与存储路径，pilot 启动遇到演示数据库必须拒绝或显式迁移，绝不把样例自动改为真实。

pilot 初期采用用户名/口令登录、哈希口令、可撤销的服务器会话及 HttpOnly/SameSite cookie；公网 HTTPS 时 Secure。写操作验证 CSRF/Origin；登录限速；角色与 workspace memberships 由服务器管理。操作者身份从会话映射到现有项目职责，请求里的 actor_id 若与会话不一致则拒绝。没有公开注册、默认管理员口令或前端任意角色切换。

每工作区单独 SQLite 业务文件，身份/成员关系位于独立控制库；路径仅由服务端注册表决定，客户端不能提交文件路径。合作团队、内部团队与 demo 不共享候选、搜索缓存、任务、输出或附件；所有 ID 查询也验证工作区。选择文件隔离是控制小规模试点复杂度；替代方案共享库行级租户键更易漏条件，现阶段不选。两文件间不做隐式分布式事务：成员关系先验证，业务写入仅在目标库提交。

### 2. 持久任务：外部调用不占数据库事务

新增 Job/Attempt、输入快照、租约、取消标记与输出记录；状态为 QUEUED/RUNNING/SUCCEEDED/FAILED/CANCELLED/OUTCOME_UNKNOWN。版本旧于当前输入的成功结果标为 STALE，保留历史但不可直接采用。任务按 workspace+业务命令+输入摘要+请求键去重；worker 起步单并发，带超时与有限重试。

第一段短事务验证权限/版本并保存 Job 与命令回执；事务外执行 provider；第二段短事务检查租约、取消及输入版本，原子保存有效输出或失败。禁止网络 I/O 放在 BEGIN IMMEDIATE 中。worker 崩溃后未外发的任务可重领；已外发但没有回执的非幂等/可能计费调用转 OUTCOME_UNKNOWN，不自动再次外发。重试决定和尝试记录可追溯，业务结果仍只能写一次。

SQLite 开启 WAL、busy timeout，使用有限连接和短写事务，初始化/迁移串行执行。暂不常驻 Redis/Postgres；当试点出现持续写竞争再独立迁移，不以调大超时掩盖事务内外网请求。

### 3. 来源适配与首批字段

两个适配器固定官方 API host，不按候选 URL 任意抓取。DataForSEO Amazon US 使用 products live advanced 小范围查询；SerpApi 使用 google_shopping、US/英文地点参数。API 认证放服务端 secret 文件；含 key 的 query 参数、请求头及错误正文先脱敏。样例适配器只允许 demo/test 环境。

来源配置声明渠道/市场、字段能力、认证引用、配额上限、留存策略和 mapping_version。默认手动触发、单次前 10 条、无评论全文/历史回补/自动日更。一个查询未必返回 10 条，空结果是正常业务状态，失败、无覆盖、限流和空结果分别显示。预算未配置时禁止无限自动重试，额度耗尽不自动充值。

每次发现生成 DiscoveryBatch 和不可变 item 快照，保存查询/地点/窗口、provider request ID、时间、字段与质量；选择纳入发送 batch/item ID，服务器检查工作区、项目、渠道、市场及批次归属，不能重新从 fixture 或不受信浏览器 payload 重建商品。

外部身份按项目+来源命名空间+市场+稳定 ID，缺稳定 ID 时使用规范化商品链接并标明强度；Google Shopping 商品 ID 不等于某商家的 SKU，不与 Amazon ASIN 自动合并。另存观察键区分同商品的不同商家报价。同一批次重复纳入不重复证据，跨批次相同商品追加来源和新观测，显式关联/替代，不按标题合并。

元数据最小必需：商品身份/链接、名称、市场、来源、采集时间。价格可缺失，币种缺失时价格不参与金额计算；税/运费、销量标签、排名、评分按实际返回标注未知或观察值。MOQ/采购报价仍来源于团队，不能从零售价推算为事实。外部事实默认未核验，负责人补充核验依据后才可供硬规则使用；人工核验动作追加新版本。

原始响应按供应商许可保存最小必要字段与摘要，设置留存期限。删除原始正文时保留获准保存的证据值、请求元数据与哈希并标注“原文已过留存期”，不得宣称原文仍可取。试点前核验账号条款支持目标团队展示；若不支持则该来源不得启用，不擅自换源。

### 4. NewAPI 有界节点

复用 d2market 的 HTTP 传输、JSON校验、usage/错误回执设计，不原样复制其模型白名单、600秒超时或额度策略。base URL 和模型由 product-res 配置注入，默认同机受控地址；配置校验限制目标及协议。当前现场模型 `deepseek-v4-flash` 只是配置起点，上线需 models 检查和一次有界 JSON smoke。

真实节点输入包含 workspace、candidate、criteria/evidence 引用、已确认人工问题、node kind、input hash。复盘节点额外绑定批准评估、指定结果版本及确定性比较结果；不能沿用“当前证据”冒充原批准假设。所有来源文本仅作为数据，隔离指令；模型无工具调用或业务写权限。

输出固定 schema；每维度保留 summary、evidence_ids、unknowns/assumptions；事实引用必须属于输入快照。复盘中的 outcome/comparison 引用使用独立类型，不与 evidence ID 混用。校验格式、引用及事实/建议分离，金额和硬规则不由模型计算。校验通过仍为草稿；输入变化、过期或跨候选引用不可采用。记录模型/提示词/schema版本、耗时、token、远端request ID与已知费用；费用未知标未知。输出总时限与 token 上限可配置，不能照抄共享服务的无限额度。

401/403/模型不可用为需配置；格式问题为可人工修正/重新运行；网络断开、已外发超时及不确定5xx为OUTCOME_UNKNOWN，提醒可能计费并等待显式新尝试。脱敏回执不能包含 key、用户敏感正文或完整网关错误页。

### 5. 回流与验收

现有 Outcome 扩展 data_origin=REAL/TEST/DEMO、来源版本和映射记录。原数据依据旧 is_demo 保持来源分类，不把历史未知类型默认提升为REAL。结果可由人工/CSV输入，必须映射到 workspace/project/candidate/approval 和 SKU/Listing/测试标识；保留输入行、来源窗口、币种、GROSS/NET。多义关系要求选择，重复源同内容幂等，异内容要求新来源修订，不暗改结果。

REAL、TEST、DEMO 分开统计；测试订单仅证明联调。真实未上市可给出原因并进入复盘，不能假造0收入。观察窗口未结束仍待结果；缺费用可以复盘已知指标但不可计算完整贡献利润。确认反馈用于新项目；原批准快照不可变。

验收分工程联调和团队试点：两个连接器均需一份有授权的真实查询回执；NewAPI需有效结构化输出；每个工作区至少一个候选从真实来源完成补证、审批、验证、真实结果或未上市原因、反馈确认与新项目采用。缺真实材料时相应 live 验收保持待办。工时可记录，不设门槛也不虚构基线；不等待盈利证明才能验收闭环。

### 6. ECS 独立发布

构建产物在本机/CI生成，独立 product-res Compose 项目仅包含gateway/api/worker，各自只读rootfs、非root用户和独立数据卷/secret；工作区库、控制库和队列包含在备份内。起步总内存上限约576 MiB（256/256/64）与单worker外部任务并发1；上线前复查余量与d2market健康，不够则保留构建产物、停止新增负载。

使用未占用的环回端口（拟18081，发布前检查），先SSH隧道完成smoke。按用户最新确认，本轮团队受控试用采用 SSH 隧道，public URL 保持 http://127.0.0.1:18081；后续再接现有域名的 Cloudflare 子域名并启用 HTTPS。需验证实际试用成员可经授权隧道登录，不能把操作者本机可达当作全体成员已获访问。未经具体入口确认不改共享80/443服务，也不修改NewAPI全局渠道/额度。发布前后对既有服务只做健康核验，不重启它们。

## Risks / Trade-offs

- [市场账号未提供] → 契约测试可继续，live验收明确等待凭据；不创建账号、接受条款或自动充值。
- [搜索覆盖不是市场全量] → 展示查询范围和时间，未知销量不补零；不承诺所有独立站被索引。
- [同机资源紧张] → 单并发、限资源、本地构建、发布前复查；必要时由用户调整机器规格。
- [引用存在不代表语义支持] → 黄金案例及人工核验，模型输出保持草稿；历史工时仅观察。
- [真实结果需要时间] → 技术联调与真实闭环分开记录；无订单时记录真实未上市情况，不制造成功样本。

## Migration Plan

先备份初版数据库；新增控制库与业务schema迁移，保留demo原数据与离线验收。生成两个空pilot工作区并通过管理命令创建成员，不从demo导入“真实数据”。先本地完整契约/浏览器回归，再ECS隔离部署及恢复演练，再配置来源/NewAPI凭据进行有界live验证，先以 SSH 隧道交付受控试用，后续开放独立 HTTPS 团队入口。代码回滚使用前一镜像；数据库已升级则停worker后恢复相匹配备份，不让旧代码直接读不兼容schema。

## Open Questions

可后补且不改变任务边界：两个来源的凭据文件引用；product-res NewAPI token及明确允许的模型别名；HTTPS域名/证书；初始成员与真实样本方向/结果表。建站平台将影响下一项自动经营数据连接器，不影响本轮人工/CSV回流合同。

## 2026-09-20 用户确认的试点调整

首轮方向为车辆内饰；两来源仍是 Amazon US 和 Google Shopping US。NewAPI 使用现有 DeepSeek 官方渠道，完成结构化 smoke 后恢复 product-res 节点配置，不主动修改共享渠道。团队入口先用 SSH 隧道；Cloudflare 子域名后续由用户提供，公网 HTTPS 要求仍保留。

## 2026-09-21 首轮研究标准

用户确认先采集与补证，采购价、MOQ、车型适配待核验，暂不设利润或 MOQ 淘汰阈值，也不批准采购。标准允许 `rules=[]`，仍要求至少一项必需证据；本轮必需字段为 price、currency、procurement_cost、moq、vehicle_fitment。没有硬规则不等于通过初筛：必需证据缺失、未经核验、过期或冲突仍须补证。后续商业阈值须经负责人确认新标准版本，不能自动套用露营演示阈值。

## 2026-09-21 已完成外部查询的人工核对恢复

DataForSEO Live 实测在 30 秒截止附近完成，应用正确保留 OUTCOME_UNKNOWN，官方免费 ID List 与 Task GET 能确认并取回原任务。新增仅供运营人员调用的恢复函数：通过现有工作区/分析负责人上下文，校验原任务状态、输入版本、供应商任务 ID、查询/市场/语言/时间窗口和成功状态，复用归一化与发现批次落库逻辑；事务内写审计并幂等关联原任务。原超时 attempt、错误和用量历史保留，不重发计费查询，不把免费恢复请求的 0 费用覆盖原查询费用。过期、取消、权限变化或无法唯一匹配时拒绝恢复。没有新增公开恢复接口，也不开放任意数据导入。

市场超时允许按来源配置，默认 30 秒，范围 1–120 秒，拒绝非有限/非法配置；本次 DataForSEO 配置为 90 秒，仍单次尝试，worker 租约 180 秒。未知结果不自动重试的规则保持不变。

# Proposal

## Why

本期需求扩大到 Amazon + eBay，并要求接入 eBay 官方接口、DataForSEO、Jungle Scout、Helium 10、卖家精灵以及更多数据源，数据层是本期重点。各数据源的接入方式（官方 API、付费 API、令牌桶、只能导出文件）、计费单位和字段口径差异很大，同一指标（例如 Amazon 销量）还会有多个互相矛盾的估算。如果每接一个工具就单独写一套采集和表结构，算法层会被绑死在具体工具上，也无法保证“不超额度”和“每个数可追溯”。

因此先建立与具体工具无关的数据层框架，再在 `add-source-connectors` 中逐个接入数据源。

## What Changes

- 数据源注册表：每个数据源声明平台/站点、可提供的数据类型、预算规格；凭据只放部署层 secret 文件，页面只显示配置状态。
- 通用额度账本：按数据源的单位（次、令牌、美元）和周期（分钟、天、月）设置硬上限与安全线，调用前在数据库事务内预扣，扣不到就顺延，从机制上保证不超额。
- 同步编排：按数据源分队列，队列级并发与速率限制；同步任务、运行记录、重试与死信；每日流水线时间按新加坡时间可调。
- 原始响应存档：每次外部响应写入对象存储（默认保留 90 天），可以在归一化逻辑修改后回放而不再花额度。
- 统一数据模型：平台商品、卖家、关键词、评论、费用预估，以及“实体 × 指标 × 日期 × 来源”的观测值；每个值带获取方式（官方 / 第三方估算 / 推算 / 手工导入）；多来源并存，按团队配置的优先级取主值。
- 文件导入：CSV / Excel 上传、列名识别与手动对应、映射模板复用、预览校验后入库，供没有 API 的工具和供应商报价表使用。
- 数据质量检查：缺失、突变、来源间差异、新鲜度、同步失败。
- 数据中心页面（对照 `docs/design/data-center.html`）：KPI、数据源卡片、同步记录、数据预览（JSON / 表格 / Schema / 原始）、导入、数据质量、额度用量。评分维度管理与 AI 助手不在本 change。
- 提供一个模拟连接器，用于在没有真实凭据时端到端验证框架。

## Capabilities

### New Capabilities

- `data-sources`：数据源注册、能力声明、启用与配置、凭据状态与核验回执。
- `source-budgets`：按数据源的额度与费用上限、事务内预扣、对账。
- `data-sync`：同步调度、按数据源的队列与流控、运行记录、重试与死信、原始响应存档与回放。
- `market-data-model`：统一实体与观测值、来源与获取方式、多来源主值选择、幂等写入。
- `data-import`：文件导入、列映射模板、预览校验与来源标注。
- `data-quality`：同步后的质量检查与问题列表。
- `data-center`：数据中心页面的展示与操作。

### Modified Capabilities

无。依赖模板带入的 `job-queues`、`job-scheduling`、`durable-workflows`、`file-storage`、`workspace-tenancy` 现有要求。

## Impact

- 新增 `packages/datasources`（契约、注册表、账本、编排、存档、导入）与 `packages/marketdata`（统一模型读写、主值选择、质量检查）；`apps/jobs` 增加同步流水线；`apps/web` 增加数据中心页面。
- 新增数据库表（见 design）；`observations` 按月分区。
- 依赖 `bootstrap-selection-workbench` 完成。
- 不包含任何真实数据源连接器（见 `add-source-connectors`），不包含算法、线索与评分维度管理。

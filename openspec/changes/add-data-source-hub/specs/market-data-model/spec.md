# Spec Delta

## Purpose

定义跨数据源统一的实体与观测值模型，保证每个数值可追溯、多来源可并列比较、缺失不被当作零。

## ADDED Requirements

### Requirement: 统一实体
系统 SHALL 以平台 + 站点 + 平台 ID（ASIN 或 ItemID）唯一标识平台商品，以平台 + 卖家 ID 标识卖家，以站点 + 关键词标识关键词；不同数据源返回的同一实体 MUST 归到同一记录。

#### Scenario: 两个来源同一 ASIN
- **WHEN** Keepa 和卖家精灵都返回 Amazon US 的同一个 ASIN
- **THEN** 系统中只有一条商品记录，两者的数值作为不同来源的观测挂在其下

### Requirement: 带来源的观测值
每个观测值 SHALL 包含实体、指标、观测日期、来源、数值、单位、币种（如适用）、获取方式（官方 / 第三方估算 / 推算 / 手工导入）和原始响应引用。同一实体、指标、日期和来源重复写入时 SHALL 以最新一次为准。

#### Scenario: 追溯一个数
- **WHEN** 在页面上查看某商品某天的销量估算
- **THEN** 能看到来源、获取方式、获取时间，并能打开对应原始响应或导入文件

#### Scenario: 当日重复同步
- **WHEN** 同一来源当天对同一商品同步两次
- **THEN** 该日该来源只有一个观测值，等于第二次的结果

### Requirement: 缺失不补零
数据源未返回的指标 MUST NOT 记为 0。读取接口 SHALL 区分“无数据”和“值为 0”。

#### Scenario: 来源没有销量
- **WHEN** 某商品只有价格，没有任何来源提供销量
- **THEN** 销量显示为“无数据”，相关计算把它当作缺失而不是零

### Requirement: 多来源主值
团队 SHALL 能为每个平台的每个指标配置来源优先级。读取时系统 SHALL 返回主值（优先级最高且有值的来源）、全部来源的值和来源间离散度。

#### Scenario: 首选来源缺失
- **WHEN** 销量估算优先级为 Jungle Scout > 卖家精灵 > Keepa，当日只有卖家精灵和 Keepa 有值
- **THEN** 主值取卖家精灵，并同时返回 Keepa 的值和两者离散度

#### Scenario: 修改优先级
- **WHEN** 团队把首选来源改为 Keepa
- **THEN** 之后的读取主值随之改变，已存储的观测值不变

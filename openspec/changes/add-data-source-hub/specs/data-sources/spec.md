# Spec Delta

## Purpose

定义数据源的注册、能力声明、启用配置与凭据状态，使上层只按“数据类型”取数，而不依赖具体工具。

## ADDED Requirements

### Requirement: 数据源注册与能力声明
每个数据源 SHALL 声明支持的平台站点、可提供的数据类型和预算规格。系统 MUST 只向声明了某数据类型的已启用数据源派发该类型的同步任务。

#### Scenario: 按能力派发
- **WHEN** 方向需要 Amazon US 的销量估算，已启用的数据源中只有两个声明了该能力
- **THEN** 同步任务只派发给这两个数据源

#### Scenario: 停用后不再派发
- **WHEN** 团队在数据中心停用某数据源
- **THEN** 之后不再为它创建新任务，已存在的数据保留可查

### Requirement: 凭据不入库
数据源凭据 SHALL 只从部署层 secret 文件读取。数据库、日志、页面和原始响应存档 MUST NOT 包含凭据明文；页面只显示“未配置 / 已配置未核验 / 核验通过 / 核验失败”及失败原因。

#### Scenario: 日志脱敏
- **WHEN** 外部调用失败并记录错误
- **THEN** 日志与运行记录中不出现令牌、密钥或带凭据的 URL 参数

### Requirement: 核验回执
系统 SHALL 支持对每个数据源执行核验：确认凭据可用，并记录关键字段是否在真实响应中出现。核验回执 MUST 保存时间、检查项与结果，供数据中心查看。

#### Scenario: 字段缺失写入回执
- **WHEN** 核验时某个声明的关键字段在响应中不存在
- **THEN** 回执记录该字段为“未返回”，数据源状态为“核验通过（部分字段缺失）”

### Requirement: 凭据失效时停止
凭据失效或权限不足时，系统 SHALL 停止该数据源当日剩余任务、不重试，并在数据中心标记为“核验失败”。

#### Scenario: 令牌被撤销
- **WHEN** 同步中外部接口返回认证失败
- **THEN** 该数据源当日剩余任务取消，状态变为“核验失败”，其他数据源不受影响
